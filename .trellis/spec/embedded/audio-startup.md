# TF WAV 启动契约

## 1. 范围
修改音频启动、FAT32目录索引或BMP/WAV共享读取时适用。不能用更早开始全卡签名扫描冒充消除定位开销。

## 2. 接口
- fat32_bmp_index.INDEX_WAV 默认0；开启时输出 wav_found/wav_sector。
- sd_card_bmp_g.INDEX_WAV 默认0，导出 wav_index_found/wav_index_sector。
- 当前top启用INDEX_WAV=1和wav_read.SCAN_MAX_SECTORS=1；wav_read默认65536保持旧调用兼容。

## 3. 同步与数据
- 首簇、几何、LBA和WAV请求均在sd_card_clk域；不引入多位异步总线。
- 首簇减2、按SPC移位、加data_start分拍；有效信号在地址稳定后发布。
- 只在目录扫描成功或仅ERR_NO_BMP时发布音频。扫描开始/SD重新初始化清有效标志；出错不发布部分候选。
- 图片数量达到8不代表WAV已扫描到；启用WAV索引时必须继续到候选或目录自然结束。
- 保持单扇区轮转仲裁和小PCM FIFO；音频不等待首图提交，不能抢占在途扇区。

## 4. 校验与错误矩阵
| 输入 | 行为 |
|---|---|
| 根目录有效短项WAV/wav、簇范围内、size≥44 | 记录首个候选 |
| 删除项、LFN、目录、卷标、非法簇、短文件 | 忽略 |
| 00结束标记后的残留WAV项 | 忽略 |
| 第8张BMP之后的WAV | 继续索引，不早停 |
| 无WAV | 目录有界结束，静音，不扫媒体像素 |
| 候选坏RIFF/WAVE | 单扇区验证结束，静音，不退回LBA0扫描 |
| 扇区错误/超时/坏链 | 不发布候选，沿现有TF错误诊断 |

## 5. 好/基线/坏例
- 好：目录定位LBA2057，直接检查该扇区，再流式PCM。
- 基线：默认INDEX_WAV=0保留原BMP提前结束行为；旧WAV测试保留默认扫描行为。
- 坏：拿旧卡固定LBA硬编码、读到任意RIFF就视为根目录文件，或声称目录首簇定位已支持碎片WAV。

## 6. 必需测试
- tb_wav_index：多簇根目录、8图之后WAV、首项优先、大小写、坏项、00后残留、错误、超时、无复位重扫和重新初始化。
- tb_wav_startup：从真实top提取控制/解析器/仲裁连接；模型计量首PCM、首图竞争上界；对比基线fixture；坏头一扇区、无文件零音频请求、SD重初始化后重新产生PCM。
- 完整回归和完整P&R；BRAM9K≤57、video setup≥0.15ns、其他域内setup/hold非负；旧SDRAM跨域负余量单列。
- 模型时间不能写成实际出声时间；后者需TF实物与屏幕接收器验证。

## 7. 反例与正确方式
错误：只取消display_valid门控，从LBA0提前扫描，会分走首图带宽，仍遍历分区/FAT/图片像素。

正确：复用目录元数据直接验证候选；限制只读一个候选扇区，缺失或坏头有界退出。当前WAV仍要求标准44字节头和物理连续存放，碎片及通用RIFF chunk支持需单独实现并测试。
