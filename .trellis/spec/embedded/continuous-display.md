# 连续曲线与双页转场契约

## 2026-10-17 SDRAM刷新补充契约

- Verilog宏为文本替换；时钟周期、除法分母与整个刷新表达式必须括号化。125MHz周期为8ns，不能把`64000000/1000000000/125000000`当成`64000000/(1000000000/125000000)`。
- 当前IP计数器比较终值后归零，终值取`floor(64ms/8ns/2048)-1=3905`，相邻自动请求为3906拍（31.248µs），不能多出归零一拍而越过刷新间隔预算。
- `sdr_init_ref.enc.v`未加密前缀有实际计数/请求逻辑。刷新回归须提取当前原文验证，不能另写理想定时器冒充IP；不解密或改写protected区。
- 理想SDRAM数组保持数据无限久，不能验证刷新。必须另测初始化、周期请求、有限忙等待ACK、超过64ms覆盖及禁用自动时的显式请求；宏头为.v也要进入该测试依赖哈希。
- 板级持久颗粒可能由装载或存储保留异常引起；确认刷新缺陷不等于已证明全部物理成因。新bit仍需多次切图与静态驻留板验。

## 2026-10-17 菜单/应急补充契约

- DE 上升沿代表新行，不能据此推进帧动画。使用 VS 或同相位的有效帧首坐标，并用完整栅格验证各行相位一致。
- 菜单预览与提交正文必须分开。已提交正文保持到 ACK；退出和继续预览不得修改在途正文，只有空闲时才允许翻转下一次提交事件。
- 播放/菜单两种按键归属都需要测试长按抑制短按；退出菜单只改变按键归属，不能意外恢复已废弃的参数页。
- 同步字库的字符索引与字符内像素列是不同地址。正常8像素宽字体使用坐标低3位取列，不能再次右移3位；固定字符串宽度应核对首尾字符，渲染测试须检查真实输出字形。
- 旧参数页被移除时，不能继续宣传它的诊断字段出现在新菜单上；按真实顶层实例与屏幕绘制分支核对。

## 1. 适用范围

变更 PCM 绘图、逐行读地址、转场参数或显示页交接时适用。老师第十二讲提供采集双 bank 和完整组发布模型，第十讲 frame_blend 提供双页互补混合模型；当前实现需适配 640×480、125MHz 存储域及现有 RGB/DE 相位。

## 2. 接口

| 模块 | 接口及范围 |
|---|---|
| disp_read_engine | ENABLE_SCROLL 默认0；scroll_x[9:0]，有效范围0..639；cmd_len[7:0]，单簇1..128字 |
| transition_ctrl | mode=0直切、1交叉淡化、2横推、3纵向揭示；ALPHA_STEP=8、SLIDE_STEP=16 |
| disp_mixer | 横推时 boundary 为源偏移，旧页用于 x<640-boundary，新页用于其余位置 |
| promax_audio_waveform | 32点；DECIMATE=120；只推进有效PCM采集；逐帧Q4平滑、统一三次B样条、消隐期曲线表、同步读一拍 |

## 3. 数据与同步

- 页基址及位移在 VS 更新；payload 两拍同步，帧 toggle 三拍同步并通过 go_pend 延后应用。等待在途读簇收尾后锁存新帧。
- 每行按 [offset,640) 与 [0,offset) 读取；源列回绕不推进行。输出累计640字才推进行基址。
- cmd_len 同时受源行剩余、输出行剩余、帧剩余和 BURST 限制。请求保持到接受；返回空拍不计字数。
- 两路 FIFO 均按 DE 排空；欠载只检查实际输出所需流。alpha=0/255 精确直通，内部权重采用既有 blend_pix 定点公式。
- 转场期间 loader 暂停，两页只读；末帧更新 A 为目标页并完整输出 B，下一 VS 才交回 A 和释放 loader。
- 波形采集组跨帧保留，采满才在 VS 发布。显示节点每帧向新目标平滑推进，避免完整组低频发布造成跳动。
- 复杂曲线在 VS 消隐期预计算，必须在活动像素前完成。同步 BRAM 查表的延迟必须替代或同步推进现有 RGB/DE/坐标阶段。禁止把整串乘法置于逐像素组合路径。
- 安路曲线表必须使用单写端口；动态列和末列使用统一地址/数据选择。检查综合实际 BRAM/FF 数，不能把仿真数组视为块 RAM 已实现。
- 源解析完成和目标写完分别锁存，支持任意先后及同拍；错误优先撤销，两端事件每次事务开始/错误/提交时清零。
- 源写请求/应答是事务隔离边界。新事务先等待请求低和旧ACK同步级回低；保留请求上下文以接受迟到ACK；新ACK前的完成不得继承。源解析成功与本次源缓存写完均到达后才启动scaler，失败源不得启动缩放。启动toggle不能因SD deinit清零。
- 顶层视频只同步管理器成功提交toggle，不能绕过该门直接同步scaler原始完成。成功同拍锁SD pending，禁止busy清零后下一拍先启动新装载。payload保持到视频释放返回。
- 手动计数是尚未启动请求数，饱和满时不能回绕或清零，启动消费1；图片索引独立循环。所有图片被本轮错误屏蔽时，新按键必须有有界重试入口，自动待请求不能无限重试。
- 新事务或错误必须清除 src_packer 的残留半字与行计数。源写尾突发长度按真实剩余字数结束。

## 4. 验证与错误矩阵

| 条件 | 规定行为 |
|---|---|
| scroll_x>=640 | 归零，不访问下一行 |
| 步长为0或SLIDE_STEP>640 | 仿真参数检查报 fatal，禁止提交 |
| 输出所需 FIFO 为空 | 输出黑像素并增加 underflow_cnt；禁止借另一页错误列掩盖丢拍 |
| PCM FIFO 为空 | HDMI 静音节拍可继续；波形不采集伪样本 |
| 采集不足32点 | 不发布未完成组，继续跨帧采集 |

## 5. 典型边界

| 用例 | 期望 |
|---|---|
| offset=0 | 与原640列读取顺序相同 |
| offset=16 | 每行先624字后16字；末尾短簇不能跨行 |
| offset=639 | 每行先1字后639字，行号只变一次 |
| 图案只有纯色 | 无法证明实际位移；必须增加按页/行/列编码的图案 |

## 6. 必需检查

- tb_audio_waveform：间距1/16/20、独立解析数学参考、正负满幅、逐帧单调收敛、消隐截止、显示期间表稳定、列连通、双bank和完整组。
- tb_source_scaler_gate与tb_top_commit_order：三种完成顺序、旧writer头部迟到、请求先撤销后ACK同步到达、错误同拍、失败零缩放/零提交、SD deinit保持事件历史，以及重试后KEY2继续处理。
- tb_image_requests：源先/写先/同拍、错误同时到达、饱和后清空再使用、累计次数超过255、物理按键消抖、全坏图恢复、唯一好图回退。
- tb_frame_writer_tail：1/16/17/31/129字、逐字地址/长度、读占用阻塞及后续事务；tb_src_packer覆盖错误后的半字清理。
- tb_disp_scroll：偏移0/1/16/127/128/639/0；逐字核对地址，含请求停顿、返回空拍和水位反压。
- tb_disp_path：默认16px和加速128px动画、真实8/8/4仲裁、两次横推/两次混合、交接后连续帧，无新增欠载；另测640×480静态帧。
- regression.sh、regression.sh --full、check_reports.py：当前 RTL、工程快照、清单和 bit 同版本。
- 板级复核未对齐短簇、真实刷新和接缝；行为模型通过不能证明物理 IP 或 setup 闭合。

## 7. 失败反例与正确做法

只让拼接边界移动而两流仍读取 x，会把旧图裁短、新图在原位置揭示，不能得到左移；正确做法是两流同时读取 (x+offset) mod 640。

动画完成即释放 loader 会允许旧页被覆盖，而 A 仍可能保留旧帧前缀；正确做法是目标 B 完整输出一帧，再交回已预取目标页的 A。

完成提交若只使用 `source_done_seen && write_finish_pulse`，源与写完成同拍时会读到旧的source_done_seen，早到的写事件也会丢失；正确做法分别锁存两端事件并纳入当前拍事件。

## 8. 面板比例与实物验证

- 不得仅凭屏幕尺寸或菜单比例推断面板有效像素。任何裁切或坐标预补偿都必须先用网格、圆形和原始 BMP 在实物上确认输入时序、缩放模式及有效比例。
- 8x16 和 16x16 字模必须以整数光栅坐标寻址。非整数坐标重采样会跳过字模列，外部显示器再次缩放后会造成笔画模糊。
- 通过自动报告只代表当前构建输入、时序报告和 bit 清单一致，不能替代实物画面验收。实物失败时必须把对应任务退回评审，并新增能覆盖失败形态的独立检查。
- 比例方案失败时先恢复上一次板级确认的完整图像和原生坐标路径；分辨率切换或新比例补偿应另建任务，禁止混入恢复版本。
- 修改 scaler、坐标映射或工程入口后，先运行基础回归；已有 TD 快照或构建清单不匹配时，必须以当前入口做完整重建，不能拿旧 bit 通过报告判断当前源码。

计数到满清零会把尚未处理的请求全部丢弃；正确做法是饱和、消费递减，图片索引单独按图数循环。

- 新增文件在最后构建前也必须纳入差异/空白检查；仅检查未暂存diff会漏掉未跟踪文件。构建后任何输入字节变化都需要刷新构建及manifest，不能提交和验证不同版本。

## 9. 多尺寸源图至720p

- 当前输入边界为BMP24、正高度、BI_RGB，宽1..1280、高1..720。源行打包步长为`ceil(width/2)`，奇数宽尾半字补零，writer总长度必须随尺寸变化。
- 源图暂存区`0x100000`与显示页`0/0x80000`分离；源完整门只启动缩放，目标460800字全部写完才向图片管理器发布完成。不能把源门toggle继续alias为目标完成。
- cfg尺寸和目标页在开始事件前稳定，并保持到完成或安全取消；start toggle跨存储时钟域后再锁存正文，忙时不得启动新源装载。
- 源行缓存按BMP底向上地址读取；输出等比居中补黑，DDA取样须与独立`floor(index*src/fit)`参考逐像素一致。
- 行缓存用32K资源，避免增加紧张的9K占用；物理块数须读报告，不能把两块逻辑RAM误报为两块物理BRAM。
- 125MHz域中源32K RAM读出至目标32K RAM写入需分拍；输出打包数据、地址与写使能同拍寄存，末字必须在整行读取开始前写入。HDMI-A逻辑坐标缩放同样需要独立流水级，HS/VS/DE必须随RGB同步增加延迟。
- 输出行须先全部缓存，再发640字不可暂停写突发；取消应收完在途读/当前写行，不发布残页，并允许下一笔正常重启。
- 720p输入仍经暂存和复制，像素恒等映射不代表装载带宽与延迟完全不变。混合尺寸、真实仲裁、源writer尾突发与板级性能须一起验证。
- 源writer的FIFO可写资格可以寄存，读写占用互斥不可延迟。下一簇长度须先锁定；离开检查或接受后清资格，回CHECK_FIFO重新采样，避免沿用上一簇充足数据状态导致读空。
- HDMI-A TMDS前缀变换与线路偏差分拍时，DE和控制符必须与像素同拍寄存；用独立逆解码、实际符号直流偏差累计、四控制符及非空白期复位检查，而非仅检查输出不再是控制符。
