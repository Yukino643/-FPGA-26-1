# HDMI-B 720p接口与构建契约

## 1. 适用范围

主节目保持HDMI-B 1280×720/60Hz；HDMI-A为共享视频时钟的720p纯视频控制台，独立逻辑画布，不读SDRAM。沿用老师第八讲整帧发布、不可撤销突发和页所有权，第十讲帧级互补混合，第十二讲采集/显示双bank；旧640回归仍验证默认参数兼容性。

## 2. 接口

- 当前顶层`bmp_read_g(MAX_WIDTH=1280, MAX_HEIGHT=720)`：接受边界内BMP24、BI_RGB、正高度；EXACT参数保留给历史固定尺寸调用与兼容性测试，不再限制当前TF素材仅720p。
- `resize_frame_720`：完整紧凑源图暂存于`0x100000`，最近邻等比居中输出空闲720p页，源和目标行使用32K RAM。所有目标字写完才发布，源完成仅作为缩放开始事件。
- `display_stream_720`：两页460800个32bit字，base=0/0x80000；每字偶列低16bit、奇列高16bit。
- `disp_read_engine(FIFO_USED_BITS=12, HIGH_WATER=1792, GATE_ENABLE=1)`：B路只在转场帧读；单突发128字。
- `disp_mixer_565`：坐标11/10bit，RGB/DE/VS两拍同相；alpha0/255精确直通。
- `promax_audio_waveform(PIPELINED_GEOMETRY=1)`：1024列曲线，节点读取、系数计算、插值分拍。
- `regression.ps1 [-SimOnly] [-Full] [-ReuseVerified]`：PowerShell7原生运行，拒绝旧manifest。

## 3. 同步与数据契约

- 源解析和writer完成必须属于新req/ACK事务；只有两者完成才发布，新ACK前旧完成不得继承。
- 地址payload在帧事件前稳定并保持至释放；VS后等待在途突发结束再采纳新基址。
- A静态读，B在alpha0帧预取；alpha255时A更新目标页，完整输出B一帧后才关闭B并释放loader。
- 2048字FIFO按奇列弹字；水位1792保留128字在途空间，禁止将偶列弹出导致隔列错位。
- 50→27→74.25/371.25MHz；前级PLL锁定稳定100µs再释放后级，功能复位等待两个PLL与系统锁定。
- 运行时间按74250000像素时钟计秒；48kHz音频采用1546/1547拍节拍。VS同拍tick计入新帧。

## 4. 验证与错误矩阵

| 条件 | 行为 |
|---|---|
| 越界尺寸或格式错误BMP | 头部错误，不发write_req，不提交页；640×480等合法小图不能按历史EXACT规则拒绝 |
| 部分写入或解析失败 | 不发布；清除半字残留与本次完成状态 |
| 所需FIFO空 | 计underflow；测试必须失败，不借用错误页掩盖 |
| TD新增critical warning | 构建失败；只允许精确旧U3/sdram ECO及单条SDRAM_CLK局部输出 |
| 新视频setup/hold负余量 | 报告失败，不能用旧SDRAM基线掩盖 |
| 构建后输入字节变化 | 清单失败，必须当前源码重新构建 |

## 5. 正常、基线与错误用例

- 正常：源图先顺序紧凑暂存，再按底向上读源行并写顶向下720p目标页；七帧静态/混合/交接完整输出。
- 基线：旧640默认参数测试使用明确fixture；不能证明新顶层连接。
- 错误：当前顶层拒绝1920×1080、1281宽、721高；640×480、1280×719属于合法输入。历史`bmp_exact720`仍单独验证EXACT模式拒绝兼容性；迟到ACK及同时完成均不得错误发布。

## 6. 必需检查

clock720官方PLL功能模型；mixer565全256alpha及首末像素；writer720两页921600地址；
bmp_exact720尺寸拒绝；commit720三完成顺序和41次请求；display720真实1650×750、刷新、
静态/双读/交接6451200像素零欠载；waveform720独立数学参考、表稳定、构建截止；
audio720三完整帧2400tick及VS碰撞；基础、完整TD、清单和报告。
新增多尺寸路径还须运行`check_resize_timing.py`，分别检查缩放器寄存器/RAM的入向与出向路径，setup/hold均须非负；不能只用旧SDRAM全局SWNS基线代替新增路径验收。
板级圆网格、KEY2多次、音频、冷启动及长期稳定性仍须实测。

## 7. 错误反例与修正

曲线节点RAM输出同拍接完整乘加链会违反74.25MHz时序；分离节点取数和系数计算，
再把除96拆成除32和有界精确除3，逐项用独立整数参考核对舍入。
仅日志出现SDRAM_CLK就放行所有PHY-5079会漏掉新增视频局部布线；逐表核对唯一网名、驱动、扇出和标记。

## 8. 下一张预取契约

- 720p顶层开启 `PREFETCH_NEXT=1`；默认0必须保持原管理器测试行为。
- 帧装载完整与可见提交是不同事件。首图例外直接提交；后台帧完成只设置prefetch_ready和尺寸，不能自行改变显示索引或提交toggle。
- 请求计数在缓存发布时消费，不在后台启动时消费。请求与消费同拍抵消，直接热按键在0计数时禁止减1回绕；满255保留已有队列。
- 已就绪页的write_buf_idx、pending_buf_idx及尺寸保持到真正发布；同拍提交锁SD pending，等待视频释放后才允许新写。
- 预取失败不制造手动请求；有界重试、坏图屏蔽及手动全坏恢复沿用原契约。SD失效撤销就绪与待请求，但不清除完成toggle历史。
- 自动计时可在后台读卡时推进，到期锁存单条auto_request_pending；关闭自动优先取消同拍自动发布，手动请求仍可发布。
- 只剩当前图有效时，自动待请求也必须能触发装载，不能只允许手动队列触发；另一页重载后照常发布。否则自动请求会永久卡住。
- tb_prefetch720覆盖真实顶层gate/CDC、首图、冷热按键、物理消抖、三完成顺序、队列饱和排空、同拍消费、错误、自动取消及重初始化；prefetch_display720覆盖实际writer与显示仲裁。
- 性能声明须区分缓存热响应、冷装载等待和动画时长。20ms消抖及帧等待为设计预算，实际按键到可见变化必须板级量测。
- 后台写图验证须将目标页初始化为非期望内容，并核对实际SDRAM接口写地址、字数和DQM；禁止预填最终图案掩盖丢写。关闭模型写使能的负例必须被像素核对拒绝。
- RTL变化后原布局种子可能发生局部hold-buffer冲突。允许使用官方place seed接口调整布局，但完整重建、未知关键警告拒绝、新视频setup/hold非负及源码清单门限不得放宽。
- TD的Clock Net Status Check阶段编号会随实际优化流程变化（本机已见7.1与9.1）；局部时钟警告解析以检查项名称截取表格，仍须逐项核对唯一SDRAM网名、驱动、扇出、数量和标记。不得因为阶段号变化放行其他局部视频时钟。
- SDRAM刷新宏及实际计数/请求测试遵守continuous-display.md的刷新补充契约；恢复刷新后同时检查ext_mem_clk域内部setup/hold非负，不能借用旧硬核跨时钟负余量基线放行。

## 9. SD装载路径与隔离时序评估

- 下一图片索引预计算、目标索引锁存和簇号/文件长度访问分拍；索引源变化需留一拍稳定窗口，不能提前用上一张图片的索引。
- 待发的元数据启动也是事务状态；SD失效必须同时撤销pending和load_start脉冲。测试须在准备拍精确注入失效，并检查正常/重试的非零簇号和文件长度，不能仅用全零表。
- MBR字节采集与新扫描清零采用独立单写时序块；不让finish_scan/超时状态机的公共控制串入整个分区表的保持mux。验证四个分区槽位、无复位重扫及superfloppy。
- BMP有效行字节数W*3在头校验准备阶段寄存，进入数据态前稳定；逐字节路径只比较寄存值，不串联宽度加法。不能改变BMP padding剥离、稀疏字节有效及像素相位。
- 宽超时比较器不能继续串入头参数和状态机公共控制；可按下一计数值寄存到期标志，但必须逐拍等价于原超时表达式。覆盖到期前取消、重新初始化和晚一拍变异体负例。
- WAV固定签名比较可分组寄存；利用sec_ready到检查态的时序窗口，避免64位比较串入扫描提交使能。覆盖无复位连续扫描坏头/好头，不能沿用上一次匹配结果。
- 仅评估综合/布线时使用evaluate_route.py的独立run，结束步骤是opt_route（不是工具命令route），不执行默认bitgen；记录输入哈希并核对原发布bit未变化。不同候选使用不同评估名称，不覆盖旧数据库。
- 检查域内SD、存储、视频、串行以及缩放寄存器/RAM路径；旧SDRAM跨域负余量单列，不得放宽约束或用全局基线掩盖新增域内违例。
- 回归结果逐项保存，run_status.json区分中断与完整完成；复用必须验证用例依赖哈希，不以旧PASS文件或results.json存在作为通过依据。
- FAT请求先锁存，再用准备拍寄存文件范围合法性、目标簇序号和簇内扇区；FAT遍历/回退复用同一请求结果，不能重新采纳客户端总线。覆盖接受后总线变化及同一文件后退再前进。
- BMP头部乘法累加与文件长度比较分拍。基础校验确认file_len>=pixel_offset后，以file_len-pixel_offset比较像素区长度，禁止offset+bytes的32位回绕放行截断文件；扇区向上取整用商加余数，避免file_len+511溢出。覆盖最大32位长度、接近末端偏移、少一字节和恰好完整。
- 布局seed保存在每次隔离flow及哈希中；已有评估名称必须在写入任何证据前拒绝，不得覆盖旧inputs/flow后才检查数据库是否存在。

## 10. HDMI-A 中文菜单渲染验收

- 中文替换卡片标题时删除原 ASCII 标题分支，不能仅在旧标题区域叠一层字模。
- 菜单中文使用原生32x32单色字模，标题仍占32x32逻辑像素；中英文状态值分区绘制，字模、列索引、命中信号与 RGB 必须保持同拍。HDMI-B旧OSD字库独立，不能一并改位宽。
- 节目页双字标题宽 64，外设页按实际两字/三字选 64/96，不能用全局卡片编号推断三字宽度。
- 两个控制菜单页不绘制底部按键提示；退出菜单后的播放操作提示单独保留。
- 菜单验收必须同时检查字模实际 RGB 像素、英文残留区域、整个菜单底部背景、双屏流水线相位，并导出两页画面人工查看。仅测试字符索引正确不能证明最终界面正确。
## 11. HDMI-B 屏幕参数菜单契约

- CONTROL 为两行三列等尺寸卡片，屏幕为索引5；二级页独立 screen_page/screen_edit，不能用原1位页面标志复用为第三页。
- 色彩档位0x144默认中性：亮度0..8对应-64..64/步长16，对比度0..8对应64..192（128为1.0），温度0..2对应-20/0/+20。边界饱和；显示对比度百分比可四舍五入，但文档注明实际12.5%步长。
- 参数只接HDMI-B的color_adjust，HDMI-A菜单不受调节。统一由菜单控制，原SW2-4不再异步覆盖参数。后级波形、OSD、应急层保持自身颜色。
- cfg与screen共用提交toggle和ACK，但正文寄存器独立于预览。未ACK时可编辑下一次预览，禁止改变正文或发第二笔提交。视频域在同一个HDMI-B VS复制所有正文。
- 进入屏幕页必须丢弃主页面尚未确认的预览，防止确认亮度顺带提交图片开关。KEY2长按：编辑取消 -> 二级页返回 -> 主菜单退出；每步不产生短按事件。KEY4长按在任何位置不能成为确认。
- 菜单中文基础32字占索引0..31：原层字槽6改为标，原空闲槽31用于题；字幕菜单字/内/容/速仍占32..35。原生32x32字模使用1024x32主bank加128x32扩展bank，禁止直接翻倍主库；scripts/gen_monitor_cjk.py生成，--check回读验证。32x32标题、16x32状态数值、同步读及整条3拍监视流水线保持。
- 验证必须提取当前顶层真实邮箱、参数译码和color_adjust实例；独立整数参考覆盖全部243种档位组合、通道0..255、负值向下舍入及上下饱和。检查确认前隔离、VS外保持、忙保护、逐级取消、恢复默认和长按抑制。
- 发布须保留完整回归状态、资源/时序报告、源码与bit哈希、主菜单和二级页仿真PNG；不能仅凭文件存在或旧PASS复用认定完成。

- Verilog-2005组合渲染路径避免嵌套函数隐式读取UI全局状态；把选择/编辑状态作为参数直接送入字形请求函数。测试须保持坐标不变只切换光标，验证组合请求随状态立即变化，防止仿真敏感列表遗漏被连续像素扫描掩盖。
- 动态字符part-select先将字符索引限制在实际4/5位，再计算逆序字节地址；不能直接用未定宽整数常量减坐标后乘8。否则TD可能生成32位进位链，即使功能仿真正确也会违反像素时钟时序。不得靠放宽SDC或旧SDRAM负余量放行。

## 12. HDMI-B 预设滚动字幕契约

- CONTROL保留两行三列，索引3为字幕入口；原cfg[3]固定文字层开关移入字幕二级页，字幕使能独立，不得删除原功能或顺带修改应急行为。
- 字幕配置5位为{speed[1:0],preset[1:0],enable}，默认0x08（正常速度/欢迎语/关闭）。内容和速度仅0..2，按键饱和；编辑预览只影响HDMI-A。
- cfg/screen/subtitle使用同一提交toggle/ACK，三个正文独立保持；busy时禁止覆盖正文。HDMI-B在同一次VS复制所有正文，字幕偏移在随后的消隐稳定；取消编辑或进入二级页不得带入其他未确认预览。
- KEY2长按逐级取消编辑、返回CONTROL、退出菜单；字幕页KEY3长按取消并返回CONTROL，主菜单KEY3长按切外设；长按不得误触发短按。KEY4长按应急优先级保持。
- 字幕条范围x[32,1248)、y[672,712)，文字y[676,708)，固定通知标记与正文分区；波形原范围y[576,672)不变。字幕开启时运行时间移到y[80,112)，关闭后恢复y[656,688)。背景各通道除2，白色字幕，青色边线；不改HDMI-A颜色。
- 字幕复用HDMI-B现有2048x32同步字体ROM，旧33字索引保留，追加实际用字后总55字；文字、列索引、背景和命中标志保持一拍OSD延迟。禁止增加第二帧缓存或改变RGB/DE/TLAST相位。
- 正文32格，每格32像素，偏移10位自然回绕；仅VS推进，慢速两帧1像素/正常每帧1像素/快速每帧2像素。不能按行或像素推进；配置变化重置到可读起点。速度单位以60Hz帧率计算。
- 页面状态到字符行提前寄存，像素路径只选行/选字；四卡二级页直接使用2x2坐标，不绕过六卡列号及宽坐标减法。主菜单和中文标题路径仍须独立检查实际P&R。
- 中文字库地址按绝对字格边界直接选择，ROM可持续读；绘制用同拍命中标志屏蔽。不得把card_x0、local_x减法、字符位置换算、卡片命中和页眉优先级同时串入BRAM地址路径；ROM在非标题区域读出的内容不能影响RGB。
- 验证三条独立字索引参考、真实RGB裁剪/透明底/回绕、60次帧事件速度、无VS保持、时间避让、预览与提交、busy保护和真实顶层相位；移除VS门控变异体应失败。保留8页菜单及3条字幕RTL截图。
- 定向时序用完整Max/Min SWNS/HWNS统计覆盖setup/recovery及hold/removal；不能因最差展示路径全为removal就推断没有hold数据。字体与缩放物理RAM另用report_cells检查全部入出引脚，ps转ns，未知/空目标拒绝。
- 发布以75项完整回归、当前源码/bit哈希、资源/域内时序门限为准；BRAM9K上限仍90%，不放宽。旧SDRAM跨域全局负余量单列，新菜单/字幕/存储域内负余量必须拒绝。

## 13. 固定文字配色与标题命名

- HDMI-B固定标题及模式文字使用天蓝色0x38BDF8，运行时间使用黄绿色0xC8F75A，字幕白色与应急后级覆盖保持。clock颜色命中寄存一拍，与同步ROM、像素列、背景同拍；不增加OSD流水级。
- 字幕二级页cfg[3]标签为“标题”，语义仍为固定标题/模式文字使能，与滚动字幕及时间开关独立。
- 菜单基础ROM仍1024x32，扩展ROM仍128x32；不能因多两个汉字翻倍字库。基础槽31已用于题，不再作为空白字索引，非标题区域靠同拍命中屏蔽。

## 14. HDMI-A 菜单 P0 视觉契约

- 依据 `docs/ui-review-20261021/proposal/UI_DESIGN_PROPOSAL.md` §8.1–8.5。本节覆盖旧菜单坐标、黄色圆点及旧配色约定，不改变第13节主屏配色，也不实施方案8.6/8.7。
