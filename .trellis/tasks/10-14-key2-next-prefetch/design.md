# 下一张预取

用户已批准持续优化、参考老师例程与Git保存，本任务按现有授权执行。

老师第八讲media_frame_loader先完成缓存，media_player_control只在完整页中选择并在帧边界发布。
当前单卡SPI约25MHz，720p BMP2764854字节，仅数据线理论下限约0.885秒，WAV/FAT/协议另增加等待。
20ms消抖与事件跨域不是1~2秒主因。

| 环节 | 实现 |
|---|---|
| 缓存策略 | PREFETCH_NEXT默认0；当前720p顶层开启1。仍用现有两页，不扩张内存 |
| 页状态 | loader完成与display提交分离；预取成功只置prefetch_ready，当前图片不变 |
| 请求 | KEY2仍饱和排队；缓存发布时消费一次；同拍按键与消费合并 |
| 仲裁 | 转场hold及发布同拍禁止新写；读取下一张只发生在另一页真正空闲后 |
| 自动轮播 | 自动到期记为一条持久请求，预取尚未完成时等待；关闭自动时清除未执行自动请求 |
| 错误 | 新ACK隔离与两完成门保留；缓存失败只跳过该候选，不能自行触发换图 |
| 冷请求 | 提前按下时等待预取完成，不能显示半帧；连续请求受存储吞吐限制 |

失败反例：预取写完成就翻转display提交toggle，会在未按KEY2时自行轮播；只有首图例外直接提交，
下一张ready后需有手动/自动请求才发布。未等转场hold解除就预取会覆盖旧页，必须保留release握手。

当前21bit/32bit存储接口可寻址8MiB，两帧占3.52MiB；四页可行地址上限不代表已验证带宽，七帧需12.3MiB不能全缓存。
本轮先验证低资源双页预取；第二块板子不解决单卡存储延迟，恢复完整第二HDMI须另测BRAM/带宽/时序。
