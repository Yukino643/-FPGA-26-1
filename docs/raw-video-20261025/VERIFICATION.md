# 320×180视频实验验证记录

本轮为独立视频实验，不覆盖旧图片发布。素材、使用和回退见 `USAGE.md`，资料取舍见 `REFERENCE_REVIEW.md`。

## 当前结果

| 项目 | 结果 |
|---|---|
| 原工程完整范围 | 88/88通过；本轮86项功能/生成检查先执行，再以输入SHA复用并追加2项当前物理检查 |
| 新播放器 | RGB565逐像素、碎片簇链、两帧后循环、发布/释放；坏头、短读、超时、中止、无文件、长度不符均通过 |
| 帧调度器 | 首帧、6VS周期、迟到保持、不追赶、复位通过 |
| 官方SPI节拍 | 真实spi_master+sd_card_cmd，每字节36个100MHz周期，512个有效数据字节；不代替实卡协议验证 |
| 全链路720p | 通过：11,980,800输出像素，2帧素材及回首帧，6VS换页，首个完整页显示后欠载增量0 |
| 板级验证 | 未执行；未改写TF卡、未烧录 |

完整回归入口 `scripts/regression_native.py`，视频入口 `scripts/verify_raw_video.py`。当前物理输入与bit由 `build_manifest.sha256` 关联；最终发布还必须核对视频仿真记录的源码SHA。

Icarus运行同一完整视频测试触及1800秒墙钟上限，未产生PASS。为保留完整720p时序和全部像素断言，改用项目build目录下的Verilator Python分发包（PyPI包标5.48.0，实际运行器报告Verilator5.49）生成C++，用本机MinGW GCC13.1/C++20编译；未缩短视频时钟周期或删减像素。原生运行器为 `scripts/verify_raw_video_compiled.py`，生成/编译日志保留工具实际版本，不能把第三方打包版本等同于厂商TD版本。

首轮编译仿真在结尾发现测试把首个尚未预取的启动栅格欠载计入播放期。原回归也排除首个启动栅格；现改为首个完整页采纳时锁存欠载基线，要求此后增量严格为零。逐像素、6VS周期和循环检查保持不变。该修正只涉及测试台，RTL与已构建bit不变。

最终完整栅格仿真覆盖283ms模拟时间，首帧ready56.205ms、采纳66.556ms；第二帧ready122.218ms、采纳166.556ms；回首帧ready222.066ms、采纳266.555ms。两次采纳间隔均约99.9999ms。以上基于每字节36拍、每扇区固定256拍等待及刷新阻塞模型，不能替代TF实卡速度测量。该端到端用例使用2帧夹具缩短仿真；实际97帧素材的文件长度和SHA已回读核对，未宣称97帧全部在完整栅格中仿真过。

## 同步与边界审查

| 维度 | 审查结论 |
|---|---|
| 时钟/复位 | 100MHz SD、125MHz存储、74.25MHz视频；复用既有复位同步与PLL，不增加时钟 |
| 页所有权 | writer只写紧凑源；scaler只写非显示页；完整目标写完才提交，视频实际采纳并释放前不复用旧页 |
| CDC | 完成用toggle，稳定页号随邮箱同步；SD pending同拍锁定，释放用返回toggle；不直接跨域传单拍事件 |
| 启动/事务 | restart后加入REARM空闲期，让旧ACK回低并重新武装完整门；源解析和源writer均完成才缩放 |
| 地址/长度 | 固定每帧115200字节、225扇区；512字节头严格校验；33位计算文件总长度；逐扇区计数512 |
| 故障 | 头/长度错误、读错误、SD中止或超时不产生完整帧提交；保留已显示页，复位恢复 |
| 字节序/行序 | RGB565小端，bottom-up源；scaler负责正向显示，不重复翻转；独立565解码参考 |
| 刷新/突发 | 不可中止突发，源写/scaler写与读互斥；全链路加入刷新阻塞，真实刷新定时另由原回归覆盖 |
| ARM/缓存/RTOS | 不适用：本实现为FPGA RTL，无外接CPU、DMA缓存或RTOS |
