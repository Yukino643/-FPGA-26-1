## 资源取舍

- 视频文件一次索引，后续顺序遍历簇链。循环才回到文件起点，不逐帧扫目录或解析BMP。
- 复用片外SDRAM源暂存、两个720p目标页及已有行缓存，不增加第三个显示页或片上帧缓存。
- RGB565每帧115200字节，225扇区；10fps有效载荷需求1.152MB/s。该数值只是文件带宽要求，不是实际帧率测试结论。
- 720p目标帧460800个32bit字，即1,843,200字节；10fps目标写流18.432MB/s，60Hz显示读流110.592MB/s。源帧读取/源写入、缩放读源与存储突发开销还需另外计算，不能漏算成9.216MB/s。
- 源读取、缩放写入串行，显示读取并行；帧完成通知与旧页释放握手分离。慢卡保持上一完整页，不补播积压帧。
- 首阶段普通WAV关闭，不增加视频音轨缓存；HDMI仍保持音频节拍，原应急警笛路径保留。
- 不照搬老师独立24bit整帧缓存：当前RGB565紧凑源与行缓存已经验证，另加缓存会浪费紧张的BRAM。

## 验证证据边界

`tb_video_spi_budget.v`连接当前真实 `sd_card_cmd` 与 `spi_master`，固定返回token/数据，只测字节周期；它不验证SD卡协议或卡实际等待时间。

`raw_video_card_model.v`按该周期建模，另给每扇区固定256拍命令等待，使用不连续簇链。其等待时间不能覆盖所有实际TF卡；实机仍需确认能连续达到10fps。

`tb_raw_video_pipeline.v`提取当前顶层实例与CDC，连接源写入FIFO、缩放器、仲裁器、刷新阻塞模型、完整720p时序和显示读出。行为SDRAM不证明加密硬核物理行为，实际资源与余量必须取本轮P&R报告。

本轮未联网检索：优先采用本机可核对的官方配套RTL、老师完赛RTL与当前工程，而非搜索摘要。
