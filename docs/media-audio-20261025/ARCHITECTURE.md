# 实现与边界

## 中文卡片

`gen_monitor_cjk.py`回收外设页专用汉字槽位，为节目/设置/媒体保留37字；其中36字使用原BRAM银行，只有“态”使用逻辑字形。基础BRAM字库尺寸不变。`monitor_menu_renderer.v`按原中文像素流水绘制媒体页“模式、播放、格式、状态”，关闭同位置ASCII标题。独立字模夹具和七个真实RTL整帧场景核对标题与ASCII残留。

## 保留显示页

媒体切换按停止新源、源/缩放/转场收尾、VS确认持页、真实存储突发排空、媒体复位握手、ACK回低重新武装执行。原`blank_video`信号现在表示持页请求，不直接门控HDMI-B黑屏。显示读链和FIFO使用全局复位，媒体复位只影响源写入与缩放等可丢弃状态。

视频域锁存`retained_front_v`，`retain_display_v`让新源加载期间两路显示地址保持旧front。页号稳定后跨两级同步到SD域，首帧写其反页。图片转场以保留页为初始front，新图片整页完成后才启动原32帧淡化。`mem_mpu`仅在当前存储突发完成后报idle，不能用固定延时或清FIFO代替排空。

切换时解除暂停可能遇到已完整写好但音频不足4800样本的pending页：停止音频生产后再等待该预算会死锁。`switching_video`由SD停止请求两级同步得到，仅在切换收尾时绕过音频预算门；页完整与VS约束仍有效。正常播放继续要求4800样本，测试必须分别覆盖两种路径。

## 原轨与共享读卡

PC转换为RV16 v2：512字节头、原有RGB565帧区、追加PCM区。v1帧区完全保留。头给出PCM逻辑起始扇区、立体声样本数、48000采样率和16bit/双声道格式。解析器对数量、总长度与溢出作边界校验。

视频与音频各有独立FAT簇链游标；`media_audio_router`将PCM逻辑扇区映射到实际LBA，与视频通过原扇区仲裁器共用TF接口，不假定文件连续。音频复用`wav_read`的单扇区BRAM和`audio_player`的512样本FIFO。暂停可继续有限预取，满后背压；不引入完整音轨缓存。

首视频页等待至少256样本。`video_frame_commit`每6VS采纳完整页，`audio_player`每视频页只消费4800样本。尾样本与VS同拍允许换页，慢帧则音频预算末停止消费，下一完整页可提交时再重启预算。暂停同时冻结视频页与PCM消费；FIFO顺序保持循环末尾到首部。

切模式停止音频新事务并等待真实idle，两侧媒体复位清FIFO；48kHz全局分数节拍、HDMI音频包、菜单与应急时基不复位。返回图片WAV从头启动。应急音源及节目音量沿原输出路径处理。

## 物理实现约束

实际资源与时序以发布`verification.json`为准，未出报告前不声称优化成功。硬门限：LUT≤16660、BRAM9K≤57、BRAM32K≤4、DSP≤15、PLL≤3；video同域setup≥0.15ns，其他同域setup/hold≥0。旧加密SDRAM跨域全局setup必须单列且不劣于−6.565ns，不能表述成全工程时序闭合。

当前构建恢复TD安装目录官方`official_strategy_ph1.json`的LogicLevelOptimize综合组合：one_hot FSM、min_ripple_len=18、balance_explore、mapper_lut_delay=2200、merge_tiny_lut=on，保留当前约束及fix_hold流程。先前普通/medium/high布局超限的日志保留，不把失败报告当成功证据。

边界标志/缩放阈值版本在seed16下视频setup为+0.140ns，未达+0.150ns发布门限。仅增加一次seed15受控候选比较，未改RTL或时钟约束；该候选video +0.375ns、SD +0.187ns、ext_mem +0.133ns、LUT16508，其他主要资源不增加。正式流程采用seed15重新完整构建并绑定清单，最终数值仍由发布报告确认；候选归档`td-seed15/physical-final/`不直接作为发布。

FAT文件大小为32位字节数，有效文件扇区下标最多23位，数量需要24位表示2^23。映射器内部下标收窄到23位，单独锁存并拒绝请求高位；簇号与物理LBA仍为32位。链长与超时计数按参数上限确定宽度，不改变精确上限和sector_done优先语义。最大文件末扇区、65535次FAT跳转、超界请求不发IO和1/2/17拍超时均单独测试。

按用户授权删除整个外设页及其蜂鸣器短时测试。KEY3长按直接切换节目/媒体；节目六卡、媒体四卡及原二级设置保留。兼容接口中的page和buzzer_test固定为0，无消费者的诊断信号由综合裁剪；真实LED输出和应急蜂鸣器仍保留。

RV16头长度校验拆成多个寄存阶段：先校验帧数范围，再计算15N、225N、75N、视频/音频扇区数和总字节数。不以未校验的音频长度字段驱动串联宽加法。文件总长保留34位比对，拒绝超出32位FAT文件大小的素材；v1/v2全帧数边界测试验证此流水与独立64位参考一致。

## 本轮局部资源与时序优化

波形平滑节点保留32×12位存储，改成单同步读口；在消隐期分时取节点并计算各列，避免多读口推断复制存储。720p仍输出原B样条结果，以独立旧算法参考逐列核对，四种窗口共143520列通过。不能仅凭单读口源码推断最终BRAM/LUT节省量，必须查看完整物理报告。

BPB基础几何校验独立寄存，字段在WAIT收齐、CHECK检查签名、PARSE消费校验；根簇号无符号`>=2`等价为`|cluster[31:1]`。缩放行读取在READ_PREP锁存末突发属性，响应末拍只消费该位，不再串联`fetch_index+1==row_words`后驱动行缓存有效位。不增加事务状态或外部周期。

参考用户提供的两篇社区文章（[文章一](https://blog.csdn.net/Pieces_thinking/article/details/147780561)、[文章二](https://blog.csdn.net/NIIT0532/article/details/148781732)）中的位宽收紧、分时复用及分拍思路；厂商属性与策略以本机安路TD及官方例程为准。文章中的通用百分比不作为本工程收益；例如8位缩为7位的位数减少为12.5%，不能写成25%。本次续接抓取文章二返回HTTP 521，全文依据上一轮已读记录，不能声称本次联网复核成功。

补充参考[资源优化实战](https://geek-doc.cn/fpga/intermediate/44-resource-optimization)的报告定位、位宽收窄、同步RAM及分时复用方法。全文缓存于`build/media_audio/references/geek-doc-resource-optimization.txt`；DSP48/Vivado/HLS相关属性不适用于本机安路工具，不照搬。以完整P&R报告衡量本工程收益，不引用文章中的通用节省比例。

BMP流内的`byte_pos>=pixel_offset`、`byte_pos<file_len`改为寄存边界标志：头部预存末跳过字节和文件末字节，连续有效输入时以相等命中更新，valid空拍保持。计数回绕时恢复与原32位无符号比较一致的初值。不得增加字节/像素延迟；独立旧实现对13种尺寸/偏移、valid间隔0/1/7逐拍比较，另检查300163组无符号比较。

FAT映射器在目标/当前簇游标更新后经过`ST_COMPARE`寄存前后关系，再由`ST_CHECK`消费。每次准备比较增加一个100MHz周期，扇区事务、链长上限、超时及错误优先级不变，禁止使用旧游标的比较结果。

缩放器在矩形准备期锁存`y_step_threshold=fit_h-height`，逐行以`y_phase>=y_step_threshold`代替先加height再比较fit_h，余量更新为`y_phase-y_step_threshold`。仅适用于现有输入不超过1280×720、只放大或等大的契约；未来支持缩小时必须重新设计，不能直接复用。现有独立坐标除法参考逐像素覆盖多尺寸与生命周期。
