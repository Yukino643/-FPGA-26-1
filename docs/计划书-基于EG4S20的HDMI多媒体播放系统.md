**作品简介中的一处更正**：EG4S20 的 SDRAM 是**片内集成**（芯片内部封装的 2M×32bit SDRAM 硬宏，经 `EG_PHY_SDRAM_2M_32` 原语直接例化），不是片外 SDRAM。答辩材料与设计说明统一按"片内集成 SDRAM"表述，这本身是 EG4S20 的差异化卖点（省引脚、免外部走线、时序裕量大）。

**不使用任何处理器**：全程纯 RTL 流水线，满足"不得带有额外处理器"红线；也不使用软核。

## 2. 应用场景定义

面向"商场广告屏 + 应急信息发布"双模终端，现场演示剧本：

1. **广告模式（默认）**：TF 卡插入后自动扫描图片与音频素材，开机即播，自动轮播；
   广告图左上显示系统标题，右上显示“广告模式”，右下显示运行时间；PCM 波形以绿色曲线叠加在图片下部；
   图片默认旧图左移、新图从右侧进入，KEY4 可选择双页交叉淡化、纵向揭示和直切；参数只在帧边界更新。
2. **交互演示**：按键手动切图；拨码+按键调亮度/对比度/色温，画面右上角实时显示参数条；
   副屏（HDMI_A）监视台显示帧率、音画同步偏差、图层开关状态、TF 卡状态等运行指标。
3. **应急模式（一键触发）**：KEY4 长按 2 s → 在视频帧边界打断广告流，全屏高对比红底白字警示
   + 底部滚动告警文字，蜂鸣器间歇鸣响，HDMI 音频切换为警笛音；再按一次返回广告流。
   切换在垂直消隐期页翻转完成，不撕裂、不黑屏。

这个剧本完整覆盖评分表里"现场演示效果"与全部 5 个扩展项。

### 3.4 关键接口结论（读源码确认）

- `sdr_as_ram`（安路加密控制器）+ `EG_PHY_SDRAM_2M_32` 硬宏：应用侧是**单端口**简单接口
  （`App_wr_en/addr/din`、`App_rd_en/addr` → `Sdr_rd_en/dout`，32bit 数据、21bit 字地址、125MHz）。
  "伪双端口"由我们在其上再包一层**多主仲裁器**实现（见 5.2）。
- `hdmi_1_4b_transmitter_core_wrapper`：视频要求一行数据连续（AXIS ready 在行尾拉低），因此读出侧必须保证行满速率供给 —— 行缓冲 FIFO 是刚需，不是优化。
- 音频口接受并行 24bit L/R + valid（48kHz），配 ACR 包（N=6144）即可；lab_ex5 用 I2S 环回是测试形态，我们直接由音频播放器给出并行流，省一层。
- BMP 解析（`bmp_read.v`）是**扇区级扫描**："BM"+宽高+24bit+无压缩 校验，图片需预先按 640×480 转换并整卡清理后写入（官方提供 convert/sync 脚本思路，我们会扩展成图片+音频+任意分辨率的统一工具）。

### 4.1 数据流框图

```
                        TF 卡 (SPI)
                            │ 扇区流
              ┌─────────────┴─────────────┐
        bmp_scan/load                   wav_scan/stream
        (BMP头解析)                     (RIFF/WAVE解析)
              │ 像素流(任意WxH RGB888)         │ PCM16×2 @48k
              ▼                          ▼
       双线性缩放引擎                音频播放/混音器 ──→ 警笛DDS(应急)
       (定点 18.14)                  │ 800样本/帧硬对齐
              ▼ 写                     ▼
   ┌──────────────────────────────────────────────┐
   │            SDRAM 多主仲裁器 (mem_mpu)          │   ← 行缓冲×N / bank交织地址映射
   │  R0: 显示读A   R1: 显示读B(转场)  W0: 素材写    │
   └───────────────┬──────────────────────────────┘
                   │ sdr_as_ram + EG_PHY_SDRAM_2M_32 (125MHz, 32bit)
   显示读出(A/B)     │
        ┌──────────┴───────────┐
        ▼                      ▼
  像素合成管线(主)          监视台合成器(副, 纯渲染)
  ├ 图层0 背景图(SDRAM)     ├ 帧率/同步偏差/图层状态文本
  ├ 图层1 滚动字幕(亚像素)   ├ 频谱镜像条
  ├ 图层2 中文字库OSD       └ 纯BRAM渲染, 不占SDRAM带宽
  ├ 图层3 Goertzel频谱条
  └ 亮度/对比度/色温管线
        │ RGB/DE → AXIS           │
        ▼                          ▼
  HDMI1.4b Core #1 ──► HDMI_B    HDMI1.4b Core #2 ──► HDMI_A
  (+音频流+ACR)                   (+静音或提示音)
        │
        ▼
```

### 4.2 时钟规划（4 个 PLL 全部排满前的分配，实际用 3 个）

| PLL | 输出 | 频率 | 用途 |
|---|---|---|---|
| sys_pll | C0 | 100MHz | TF 卡 SPI 与扫描控制域 |
| sys_pll | C1 | 125MHz | SDRAM 控制器主时钟 |
| sys_pll | C2 | 125MHz / 180° | SDRAM 移相采样时钟 Clk_sft |
| video_pll | C0 | 25.175MHz | 视频像素时钟（640×480@60, VIC=1） |
| video_pll | C1 | 125.875MHz | TMDS 5× 串化时钟 |

两路 HDMI 均用 640×480@60，共享 video_clk；音频并行流在现有时钟域内由分数累加器产生平均 48 kHz tick，不再引入未使用的 audio_pll。

### 4.3 SDRAM 地址映射与带宽预算

片内 SDRAM：2M 字 × 4B = 8MB，字地址 21bit。规划：

| 区域 | 字地址范围 | 容量 | 用途 |
|---|---|---|---|
| DISP_BUF0 | 0x0_0000 ~ 0x4_AFFF | 307,200 字 (1.2MB) | 显示帧缓冲 A（640×480×32bit，低 24bit=RGB） |
| DISP_BUF1 | 0x4_B000 ~ 0x9_5FFF | 307,200 字 (1.2MB) | 显示帧缓冲 B（页翻转/转场另一图） |
| SRC_BUF | 0x9_6000 ~ 0xF_5FFF | ≤393,216 字 (1.5MB) | 缩放源图暂存（最大 1024×768×RGB565） |
| 保留 | 0xF_6000 ~ 0x1F_FFFF | ~0.7MB | 备用（更多帧缓冲/素材） |

**带宽预算**（SDRAM 125MHz×4B 峰值 500MB/s，按保守 55% 有效利用率 ≈ 275MB/s）：

| 场景 | 读 | 写 | 合计 | 结论 |
|---|---|---|---|---|
| 稳态显示 | 显示读 1 字/像素时钟 ≈ 100.7MB/s | 素材写 ≈ 4MB/s | ~105MB/s | 富余 ~2.6× |
| 转场（双图混合） | A+B 各 100.7MB/s 交替 | 素材写暂停 | ~202MB/s | 仍留 ~35% 裕量 |
| 缩放装载 | 源图行流读 ~6MB/s | 缩放写 ~4MB/s | ~10MB/s | 极充裕 |

bank 交织映射：`word_addr = {bank[1:0], row[10:0], col[7:0]}`，把相邻显示行映射到相邻 bank，配合 256 字突发使读出流几乎无 row-miss；行缓冲（≥32 字×2 FIFO）吸收仲裁切换抖动。

### 4.4 资源预算（目标 ≤85%，超限时的削减路径见第 9 章）

| 模块组 | LUT(估) | DFF(估) | ERAM9K(估) | M18x18(估) |
|---|---|---|---|---|

## 5. 关键技术方案（逐项实现方法）

### 5.1 TF 卡素材扫描与 BMP/WAV 解析（改造官方模块）

- 保留官方 `sd_card_top`（SPI 初始化 CMD0/CMD8/ACMD41 等 + 单扇区读）与 `spi_master`。
- `bmp_read` 泛化：不再锁死 640×480——扫描阶段记录 `BM` 魔数 + 24bit + 无压缩的图起始扇区与**文件长度**；装载阶段按 header 里 `width/height/pixel_offset` 流式输出像素（含行 4 字节对齐补齐、自底向上翻转）。输出统一 24bit RGB 像素流。
- 新增 `wav_read`：扇区扫描 `RIFF....WAVE`，解析 fmt 块（要求 PCM、48kHz、16bit、双声道），data 块流式输出；扫描上限 8 个图片扇区 + 4 个音频扇区。
- 上位机脚本 `scripts/prepare_media.py`（扩展官方 convert 思路）：任意图片 → 统一 BMP、任意音频 → 48k/16bit/stereo WAV、整卡物理清理后按序写入，规避扇区残留死锁。

### 5.2 SDRAM 伪双端口帧缓存管理（自研核心亮点①）

在官方 `sdr_as_ram` 单端口之上实现 `mem_mpu` 多主仲裁：

- **主端口**：R0=显示读当前页（最高优先级、周期性），R1=转场第二页读（仅转场期间），W0=素材装载写。
- **调度**：R0 每行预留固定窗口（DE 期间独占），消隐期把时间片让给 W0/R1 —— 显示路径零等待，行缓冲 FIFO 深度按"消隐时长可写入行数据"计算（640×480@60 行消隐 160 像素 ≈ 6.4µs，足够 256 字突发 3 条）。
- **bank 交织**：帧缓冲按 bank 交替布局（见 4.3），读突发顺序与 bank 激活错开。
- **无撕裂页翻转**：`disp_buf_idx` 只在 vsync 消隐期翻转；装载完成 toggle 事件（沿用官方跨域 toggle 握手）在下一场消隐生效。
- **转场双页读**：两路显示读引擎分别预取 A/B 页并由异步 FIFO 对齐消费；直切只改变帧边界页归属。默认横向推移同时改变两页逐行读取坐标和拼接位置；可选交叉淡化使用两页互补权重，不经过黑场。SD 装载器在提交确认前暂停，避免覆盖仍被显示读取的页。

### 5.3 双 HDMI 异显（自研亮点②）

- HDMI_B：主内容，合成管线输出 → `hdmi_1_4b_transmitter_core_wrapper` #1 → `hdmi_phy_wrapper` #1（4×`lane_lvds_10_1`，ODDR 10:1 串化）。
- HDMI_A：监视台，`monitor_compositor` 纯 BRAM 渲染（黑底 + 字库文本行 + 频谱镜像 + 状态色块）→ 同型号核 #2 + PHY #2。两路时序相同（640×480@60, VIC=1），共享 PLL。
- EDID：两核各自通过 DDC 读取（KEY 触发或上电自动），监视台显示 EDID 读取结果。
- 官方例程已分别验证两口作 TX 的可行性，风险点只剩"同工程双实例"的资源与时序收敛，属编译问题非方案问题。

### 5.4 图片 OSD 与 PCM 时域波形

当前主显示链路为：

```
双缓冲图片 → 色彩调节 → PCM 波形曲线 → 透明黑色字库 OSD → 应急覆盖 → HDMI_B
```

- OSD 使用同步字库 BRAM，标题“炬屏—双模HDMI多媒体系统”在左上，模式在右上，运行时间在右下。文字为黑色；非字形像素透传图片，不铺顶部或底部背景条。
- 主显示不叠加滚动字幕或 Goertzel 频谱柱。HDMI_A 仍是独立监视台。
- PCM 波形沿用老师第十二讲的真实有效样本、32点乒乓缓存与完整组VS发布；当前每120个有效样本抽取一个，约覆盖80ms。相邻点有符号插值并补齐陡坡，常规三像素连续曲线，幅度饱和裁剪；保留中轴线和右侧单点峰值表。静音PCM显示为平线，未采满组不提前发布。
- 图片提交默认双页横向推移，每帧16px，40帧约0.67秒；KEY4可选择交叉淡化、纵向揭示和直切。参考老师第十讲frame_blend的双页互补权重与帧推进；两页保持只读，末帧B直通完成后才交回A并允许下一次装载。

### 5.5 音频可视化实现边界

- 主显示波形直接使用 `audio_player` / 应急音源选择后的 PCM 样本，不依赖 FFT/Goertzel幅度结果。
- Goertzel 模块源码保留在工程中供既有音频分析功能使用；当前主画面不实例化频谱柱图层。不得将主画面描述成“正在显示频谱”。
- 若没有 WAV 音频且应急音源关闭，PCM 为静音，波形平直属于正确结果。

### 5.6 音频输出与音画同步（评分项）

- `audio_player`：WAV 流 → 512 深异步 FIFO（TF 100M 域 → video_clk 域）→ 按帧供给 24bit L/R（48kHz），quantization 16→24bit 左移。
- **硬同步机制**：48000/60 = 800 样本/帧整除。以 `frame_cnt×800` 为基准做样本计数闭环：FIFO 水位正常时逐样本输出；每帧末检查累计偏差，|偏差|>阈值则本帧补 1 或弃 1 样本，保证**音画同步误差恒 <1 帧**（≈16.7ms）。
- ACR：沿用 `audio_arc_calculate`（N=6144）自动测 CTS。
- 应急音频：警笛 DDS（频扫 400→1200Hz 锯齿包络）在帧边界无缝替换 WAV 流。

### 5.7 音画同步偏差测量（监视台核心指标）

`av_sync_dev = audio_sample_cnt − frame_cnt×800`，带符号显示于监视台（单位：样本）。该指标同时是"补弃样本"闭环的输入，演示时能直接看到闭环把它压回 ±1 帧内——把评分项"音画同步"做成了**可测量、可展示**的系统能力。

### 5.8 交互控制

| 控件 | 功能 |
|---|---|
| KEY1（物理 KEY2） | 手动下一张（触发装载+转场） |
| KEY2（物理 KEY3） | 自动轮播 开/关（默认开，10s 间隔可调） |
| KEY3（物理 KEY4） | 短按循环切换转场；长按 2 s 进入/退出应急 |
| rst_n（物理 KEY1） | 外部低有效复位，不参与业务按键 |
| SW1~3 | 亮度/对比度/色温档位（配合 KEY 增减，参数 OSD 回显） |
| SW4 | 字幕/OSD/频谱图层总开关（演示用） |
| 蜂鸣器 | 应急模式 1Hz 断续鸣响（H11 低有效；受 SW5 硬件开关保护） |

### 5.9 定点双线性缩放（扩展③）

- 装载路径：BMP 源图先整帧暂存 SRC_BUF（RGB565，≤1024×768），随后 `scaler` 以 18.14 定点步进 `dx=W_src<<14/640, dy=H_src<<14/480` 逐目标行计算源 y，两行缓存在 2×行缓冲 BRAM，双线性 4 点加权（4×M18x18）输出 RGB888 写入目标显示缓冲。
- 缩小用逐系数取整 + 半像素中心对齐（`x'=(x+0.5)·k−0.5`），避免边缘偏移；放大时自然插值。
- 装载期间显示照常（读旧页），装载+缩放整体耗时约 0.6~1.0s（受 TF 读速主导），完成 toggle 后下一场消隐提交，进度提示显示于监视台。

### 5.10 亮度/对比度/色温硬件管线（扩展④）

```
R' = clamp(((R−128)×C)>>8 + 128 + Br + T)
G' = clamp(((G−128)×C)>>8 + 128 + Bg)
B' = clamp(((B−128)×C)>>8 + 128 + Bb − T)
```
C=对比度 0~255（128=1.0），B=亮度偏移，T=色温偏移（暖屏 R+、B−；冷屏反向）。全流水单周期，位于混合之后、HDMI 核 AXIS 之前。参数值由 OSD 图层实时回显（数值+条形），按键/拨码改变立即生效。

### 5.11 应急模式状态机（应用亮点）

- 触发：KEY4 长按 → `EMERGENCY_PENDING`，**当前帧播完、下一场消隐**切换：
  视频源切为应急渲染器（高对比红底 #C00000、白字警示标题 24×24、黄字滚动告警条、倒计时），音频源切警笛，蜂鸣器启动。全程 ≤1 帧，与音画同步目标一致。
- 退出：再次 KEY4，同样消隐期切回广告流（字幕/参数状态全部保留）。
- 应急渲染为独立小状态机 + 字库 ROM，不访问 SDRAM，绝对可靠。

## 9. 风险与预案

| 风险 | 概率 | 预案 |
|---|---|---|
| ERAM 超限（预算 96%） | 高 | 首砍：频谱 FIFO 降深、字幕行缓冲 1bpp 化；次砍：监视台文本行复用主 OSD ROM；极限：HDMI 核减为单实例+VGA 监视口（保底方案，赛题允许 12 位 VGA） |
| 转场双读时 SDRAM 带宽不足 | 中 | 转场期降为隔像素取 A/B（视觉等效）；或转场期间把混合矩阵改为 16bit 中间精度；仍不行则淡入淡出改为"黑场渐变"（单读） |
| HDMI_A 口 LVDS33 TX 时序/电气兼容个别显示器 | 低 | 官方例程已验证该口作 TX；若遇兼容性，监视台改经 VGA 口输出（板载 12bit VGA），主通道不受影响 |
| TF 卡兼容性（SPI 模式时序） | 中 | 保守 SPI 时钟（初始化 400k → 12.5M 分档）、CMD8/ACMD41 完整握手、超时重扫；官方模块已过验证，仅扩展解析 |
| 双 HDMI 核 + 全管线时序收敛 | 中 | 25.175MHz 像素域裕量大；125M 串化域路径短（寄存器在 ODDR 前）；必要时 pipeline 重切 + multicycle path 约束 |
| 资源不够放双 HDMI 核 | 低 | 两核共用同一时序，可改"1 核 + 2 PHY"变体（TMDS 编码后扇出到两路 ODDR），省 ~1.7K LUT |
| 音画同步闭环振荡 | 低 | 补/弃样本带滞回与每帧限 1 次；偏差死区 ±16 样本 |
