# 运行时媒体融合：实现与参考

## 资源复用

上电图片，运行时选择图片/RV16。`media_source`内的BMP和RV16解析器共用一套FAT目录索引和碎片簇链映射；未选解析器保持复位。源writer、RGB565紧凑源暂存、最近邻缩放器、720p两目标页和显示读出均复用。没有第二套整帧缓存、额外PLL或MP4解码器。

RV16固定320×180、10fps、RGB565小端bottom-up：每帧115200字节，225扇区，头512字节；目标1280×720为4倍整数放大。素材97帧、9.7秒；10fps是目标换页节拍，慢卡保持上一完整页，不追赶补播积压帧。

## 切换与时钟域

| 阶段 | 条件与动作 |
|---|---|
| RUN→STOP | 锁定请求，立即阻止下一源帧；当前完整源事务/缩放/转场收尾 |
| BLANK | 视频域在VS应用黑场，SD域等待返回确认 |
| DRAIN | 存储域阻止新显示读命令，已接纳突发继续完成；等待真实空闲 |
| RESET | 媒体源与两端FIFO/toggle链同时复位；模式在复位保持期更新 |
| RELEASE | 各域同步释放复位，不能沿用上次完成事件 |
| RESUME→RUN | 黑场和排空确认回低，重新开始目标媒体装载 |

PLL、HDMI时序、SDRAM硬核、WAV、菜单、应急不随模式切换复位。请求/应答为保持到确认的电平，多位帧地址为稳定负载加事件握手。视频完整页在6个60Hz VS间隔采纳，旧页释放返回SD端后才允许复用。

暂停时完整待提交帧可能占住邮箱；切模式时暂时放行换页，随后按VS黑场/排空，防止等待源空闲与暂停互锁。不能用固定延时假装SD扇区或存储突发完成。

## 验证证据与边界

### FAT超时控制的局部化

融合后完整P&R曾发现`timeout_hit`扇出进入MBR/BPB解析寄存器的时钟使能，造成SD域setup违例。超时只能在四个WAIT态且`!sector_done`时成立，因此将超时结束操作移到状态机case之后，仅覆盖状态、错误和完成标志；不再用它包住全部解析逻辑。到期拍与完成优先级保持不变，1、2、17拍边界均有测试。未放宽时钟约束。

seed16初次SD域setup为−0.179ns；仅改seed17为−1.195ns，不能发布。采用上述RTL修正、恢复seed16后，SD域setup为+0.216ns；其余最终结果见`VALIDATION.md`及发布`verification.json`。布局种子不能替代控制路径修复。

- 原图片/WAV完整回归：保留原测试与真实顶层提取，含多尺寸、自动周期、图层、字幕整圈、音量、应急及双屏像素。
- 媒体单元：异步时钟排空握手、暂停待提交返回、真实消抖长短按/取消/busy、媒体页7场全栅格独立参考。
- 媒体整链路：真实writer/scaler/读写仲裁、720p逐像素、VS换页，SD模型与WAV竞争。坏头和缺R16单独测试返回图片。
- 正常链路记录：图片5529600像素、视频52531200像素；536次WAV扇区读取、68453次PCM消费，启动后无新增音频欠载。它们是仿真模型数据，不是实卡测量。
- 原RV16解析器9项测试保留，包括真实SPI周期预算和错误路径。模型固定命令等待，不能覆盖所有TF卡延迟。
- 字幕Icarus完整栅格超过1800秒，不记PASS；改用同一测试台的Verilator编译仿真，仍保留3背景×8组合及3句×3速×2时间窗口共18整圈。
- 存储行为模型不能证明加密SDRAM硬核；完整P&R和定向物理时序另行检查，板级验证仍由用户执行。
