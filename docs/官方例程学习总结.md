# 官方例程学习总结 — 优化策略提炼

> 基于 `lab_ex5_i2s` 和 `lab_ex4_tf` 官方例程的深度分析
> 提炼可直接应用到本项目的优化策略

---

## 1. 官方例程架构分析

### 1.1 lab_ex4_tf（纯视频版）

| 模块 | 功能 | 关键设计 |
|---|---|---|
| `sd_card_bmp` | TF 卡扫描/装载控制 | 双缓冲提交，write_finish_toggle 跨域握手 |
| `bmp_read` | BMP 扇区解析 | 固定 640×480，24bit，无压缩 |
| `frame_read_write` | SDRAM 帧缓存读写 | 双缓冲地址切换，读写互斥（写优先） |
| `video_timing_data` | VGA 时序生成 | 宏定义可配分辨率 |
| `video_rgb_to_axis` | RGB→AXIS 打包 | SOF/valid/last 信号 |
| `hdmi_1_4b_transmitter_core` | HDMI 1.4b 发射 | EDID 读取 + TMDS 编码 |

**资源占用**：~2,678 LUT（基线实测）

### 1.2 lab_ex5_i2s（视频+音频版）

在 lab_ex4 基础上增加：
- `hdmi_audio_tone_i2s_64fs`：I2S 测试音生成
- `I2S_receiver`：I2S 解串 → 24bit PCM
- `audio_arc_calculate`：ACR 包参数计算（N=6144）

**关键设计**：音频样本在 video_clk 域输出，与视频共用 HDMI 核的数据岛包通道。

## 2. 可借鉴的优化策略

### 2.1 POR 上电防抖复位（官方已实现，我们需对齐）

官方设计：所有 PLL 完全锁定且稳定后才启动系统。

```verilog
// 官方模式：PLL lock 级联复位
wire rst_all = ~rst_n | ~pll_locked;
```

**我们的现状**：已有 `rst_all = ~rst_n | ~audio_pll_lock`，但只等了 audio_pll。
**优化**：应等待所有 3 个 PLL（sys_pll、video_pll、audio_pll）全部锁定。

### 2.2 SD 卡防死锁（官方已实现，我们需对齐）

官方设计：1 秒超时自动中止并恢复控制权。

**我们的现状**：`bmp_read_g` 有超时机制，但 `wav_read` 没有。
**优化**：给 `wav_read` 加超时保护。

### 2.3 SD 卡同步工具（官方提供，我们需集成）

官方 `sync_to_sd.py` 的核心洞察：
- 直接删除旧图片**无效**（物理扇区残留）
- 必须先破坏旧 BMP 的 `BM` 魔数
- 再清空文件系统
- 最后写入新图片

**我们的现状**：`scripts/` 目录有 `prepare_media.py`（计划中），但未实现。
**优化**：移植官方 `sync_to_sd.py` 并扩展支持 WAV 文件。

### 2.4 双缓冲无缝切换（官方已实现，我们已对齐）

官方设计：
- `write_buf_idx` / `disp_buf_idx` 分离写入和显示缓冲
- `write_finish_toggle` 跨时钟域握手
- 切换在 vsync 消隐期完成

**我们的现状**：已实现，且扩展了转场引擎（淡入淡出/滑动）。

### 2.5 视频时序可配置（官方已实现）

官方 `video_define.v` 用宏定义配置 VGA 时序：

```verilog
`define H_ACTIVE 640
`define H_FP     16
`define H_SYNC   96
`define H_BP     48
// ...
```

**我们的现状**：`video_timing_gen.v` 已参数化，但没有统一的宏定义文件。
**优化**：创建 `video_define.vh` 统一管理时序参数。

## 5. 官方工具链借鉴

### 5.1 图片转换脚本

官方 `convert_images_to_bmp.py` 的优点：
- 支持多种输入格式（JPG/PNG/WebP/GIF）
- LANCZOS 高质量缩放
- 批量 + 单文件双模式

**我们的改进方向**：
- 支持任意目标分辨率（不只是 640×480）
- 支持 WAV 音频文件打包
- 支持字幕文本文件

### 5.2 SD 卡同步脚本

官方 `sync_to_sd.py` 的核心价值：
- 物理扇区残留防护（破坏旧 BM 魔数）
- 顺序编号保证物理连续性
- 安全拦截系统盘

**我们必须移植**：这是上板验证的关键工具。
