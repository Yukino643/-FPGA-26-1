# 返回首图提速：范围与边界

## 根因与取舍

视频帧只有 320×180 RGB565（115200 字节），720p BMP24 像素约 2764800 字节，两者大小差 24 倍。返回图片要恢复图片索引、读首图并生成完整目标页，不能把两方向的等待视为同一种操作。

普通图片的 ALPHA_STEP=8，0 到饱和 255 需要 32 个 VS；返回也沿用了这段约 0.533 秒的动画。本次仅把返回首张改为步长 32、8 个 VS（约 0.133 秒），减少 24 个 VS，约 0.4 秒。提交等待、首个 VS 和 SETTLE 交接仍保留，这不是总返回时间的测量值。

参考老师“第十讲：图片转场特效”的 frame_blend.v：只在 frame_start 推进权重。继续使用本工程已有双页控制与 255 饱和逻辑，不直接套用其他时序或宽度。

## 实际修改

| 文件 | 修改 | 不变量 |
|---|---|---|
| rtl/video/transition_ctrl.v | 可选 RETURN_SPEEDUP、RETURN_ALPHA_STEP；首笔提交时锁存 fast_blend | 默认参数关闭加速；后续事务仍用 ALPHA_STEP |
| rtl/top/top_tf_hdmi_audio.v | 本实例开启加速，return_from_video 接已有 retain_display_v | 不新增 CDC；视频期间控制器复位，上电 retain=0 |

| scripts/regression_native.py | 增加返回转场检查 | 原有用例完整保留 |

## 并发与时序审查

| 项目 | 结论 |
|---|---|
| 寄存器/中断/RTOS/CPU缓存 | 纯 RTL，未引入这些软件机制 |
| 多时钟域 | 只复用已存在的视频域持页信号；不新加同步总线 |
| 属性生命周期 | 在接收完整页提交时锁存；提交后外部信号变化不能改变本次步长 |
| 页完整性 | 新页装载完成才提交，仍只在 VS 开始和推进 |
| 页所有权 | 目标页翻转后保留 SETTLE 一帧，再释放装载；禁止写当前可见页 |
| 启动/复位 | 开机首张不加速；视频期间控制器复位，为每次返回重新武装 |
| 数值边界 | 9 位求和，>=255 饱和；禁止使能后步长为 0 |
| 兼容性 | 默认关闭新功能；普通切图、其他转场和媒体音频链无功能修改 |

失败反例：全局改 ALPHA_STEP 会改变普通切图；直接跳过 SETTLE 释放 loader 可能覆盖读链仍在使用的页。本次均不采用。

## 验收口径

原功能完整回归、四组真实顶层媒体流水和固定旧转场逐拍等价均须通过，再做完整综合/P&R/bitgen。门限：LUT≤16660、BRAM9K≤57、BRAM32K≤4、DSP≤15、PLL≤3；video 域 setup≥0.15ns，其余域内 setup 与全部 hold 非负。原加密 SDRAM 跨域 setup −6.565ns 单列。

真实卡读速与最终总耗时属于板级验收。软件通过不代替双屏、有声循环、暂停返回与应急的实际检查。
