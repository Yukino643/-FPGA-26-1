# HDMI-B 720p 首版

输出 1280×720、16:9、60Hz；像素时钟74.25MHz，TMDS串行371.25MHz。
工程入口 `td_prj/av_media.al`，固件 `td_prj/av_media_Runs/phy_1/av_media.bit`。

## 素材与板测

1. TF卡维持FAT32。先在电脑备份卡内容，再移走旧640×480 BMP。
2. 从 `D:\FPGA\音频\图片比例补偿\素材汇总_20261012\处理图` 复制以下七张到卡根目录：
   BEACH720、NAIL720、ROOM720、NIGHT720、NAIL1720、NAIL2720、MONST720，扩展名 `.BMP`。
3. 本版仅接受1280×720、24位无压缩、正高度BMP；其他尺寸会报头部错误并跳过。
   不会在板上自动把2K/JPEG/PNG缩到720p，必须先在电脑处理。
4. WAV沿用之前已经验证的PCM文件。安全弹出卡，插入开发板，再下载本轮新bit。
5. 显示器连接HDMI-B，菜单应显示1280×720/60Hz，选择原始/自动/16:9显示。
   HDMI-A首版暂停；不能用A口判断本版是否正常。
6. 检查七图颜色、方向、无蓝边/撕裂，物理KEY2连续40次切图；KEY3控制自动播放；
   KEY4长按2秒进入/退出应急，短按不再改变转场。
7. 检查交叉淡化约0.55秒，无黑场或残留；音频连续，波形圆润且逐帧变化。
8. 冷启动录像测量首图出现时间，上电3秒是目标，软件验证不能代替实测。

几何校准图在 `build/720p/previews/GRID720.BMP`。单独替换卡中的一张测试，
检查圆形横纵直径误差≤5%、红色四边完整；不要同时把所有预览文件复制到卡里。

## 实现与老师资料的对应关系

| 资料 | 吸收的设计原则 | 本工程适配 |
|---|---|---|
| 第八讲 media_frame_loader/media_frame_reader | 整帧成功才发布、在途突发不可撤销、FIFO容量预留 | 原有ACK隔离和双完成门、128字突发、2048字显示FIFO |
| 第十讲 frame_blend | 双页互补权重、帧边界推进alpha | 两级RGB565解包/混合、精确端点、交接后才释放旧页 |
| 第十二讲 promax_audio_waveform | 采集/显示双bank、有效PCM抽取、完整组发布 | 32点/80ms窗口、逐帧平滑、B样条消隐构建、同步BRAM查表 |

两显示页每页460800个32位字，地址0与0x80000，各约1.76MiB。
BMP24在写入时转RGB565，每字低半字为偶列、高半字为奇列，writer反转行地址抵消BMP底向上存储。
首版取消scaler和HDMI-A实例，以减少LUT及读写带宽。静态只读A，淡化才开启B；
首个alpha=0帧预取B，alpha=255帧完成交接后才停止B并释放loader。
外部面板缩放不会恢复RGB565的颜色精度；720p提高像素细节，渐变仍可能有量化色阶。

```powershell
pwsh.exe -NoLogo -NoProfile -File scripts/regression.ps1 -SimOnly
```

## KEY2下一张预取（2026-10-14）

纯RTL没有软件中断优先级。原实现KEY2消抖20ms之后才开始读整张BMP，
每张2764854字节；100MHz SD域、官方SPI分频0对应约25MHz，单纯串行数据理论下限约0.885秒。
FAT簇链、命令/字节间状态机、WAV共享及写缓存另外增加等待，符合板上观察的1~2秒。
上述为代码与带宽分析，不是对每段延迟做过板级测量。

参考老师第八讲 `media_frame_loader` 的完整页标记和 `media_player_control` 的帧边界选择，
当前720p顶层启用 `sd_card_bmp_g(PREFETCH_NEXT=1)`。首图完整后立即提交；
之后在空闲页提前读取下一张，成功只置就绪，不自行轮播。KEY2请求才发布已完整的页，
视频域在VS启动原有交叉淡化。转场结束及旧页释放返回SD域后，才能再次预取。
参数默认0，旧640及旧管理器回归保留原行为。

| 情况 | 响应边界 |
|---|---|
| 下一张已就绪、无转场和积压 | 消抖约20ms后数个时钟拍提交；等待VS及首个非零alpha帧后开始可见变化，设计预算约20~55ms，待实测 |
| 下一张尚未读完 | 请求排队，等待剩余读卡时间；不能承诺所有按键都立即切图 |
| 转场中再次按键 | 先排队，等转场结束、旧页释放、下一张加载完成再处理 |
| 坏候选 | 重试一次后跳过；不发布半帧，不制造新的手动请求 |
| 只有一张可用图 | 不做无意义后台循环读；真实按键或自动到期请求仍可重载到另一页完成握手 |

仍使用原两页RGB565，不提高SPI速度。累计按键次数不限，尚未处理请求最多积压255条；
满时保留已有队列，新事件不会让计数回绕。自动轮播到期为一条持久请求，关闭自动即取消。
诊断状态 `[28]` 表示下一张预取就绪，`[29]` 表示自动切图待请求。

新增 `tb_prefetch720` 使用当前顶层事务门、CDC和转场原文，验证首图、41次热切、冷请求、
真实消抖缩比、300次输入饱和后255条排空、并发消费、坏图跳过、自动取消及SD重新初始化。
`prefetch_display720` 保持真实1280列/74.25MHz和125MHz存储、刷新阻塞，
以8行缩短仿真；实际128字writer约1.95Mword/s供给（高于当前SPI上限），
后台完整写入另一页后淡化，逐像素检查及显示欠载均设硬失败。
目标页先填非期望毒值，并核对实际存储写地址、DQM及总字数；关闭模型写入的负例由像素检查拒绝。
完整720行显示压力测试另行保留，缩行并行用例不等于整幅带写实物验证。

上板验证：下载本轮bit，关闭自动播放。首图出现后停留至少2秒，再按KEY2，
观察动画是否很快开始；每次转场结束后也停留至少2秒，循环七图及连续40次。
另测连续快按、播放WAV时切图、长期待机；记录按下到第一处画面变化的时间，
不要把约0.55秒的动画完成时间当作按键启动延迟。
本轮预取响应、预取期间音频及显示完整性仍须实物复核。

| 寄存器 | 7903/19600 | 40.32% | 11697 |
| BRAM9K | 49/64 | 76.56% | 15 |
| BRAM32K | 0/16 | 0% | 16 |
| DSP | 9/29 | 31.03% | 20 |
| PLL | 3/4 | 75.00% | 1 |
| 全局时钟GCLK | 3/16 | 18.75% | 13 |
| 物理PAD | 48/188 | 25.53% | 140 |
| 报告逻辑IO端口 | 40/188 | 21.28% | 148 |

逻辑IO含输入10、输出28、双向2。物理报告另列LE已使用13223（仅LUT5320、仅寄存器1659、
LUT与寄存器共用6244）；LE这一行没有给出总容量，不据此另造占用百分比。
IO打包寄存器为输入3、输出21、三态1，FIFO9K独立原语为0（FIFO存储可实现为BRAM）。
BRAM、DSP和PLL与已上板的上一版相同。最终使用布局种子6；不同种子的物理优化会改变
LUT和寄存器数量，不能将两次物理报告的差值直接视为预取逻辑的独立开销。

当前HDMI-B 720p图片、交叉淡化、WAV和波形由单板承担，资源余量足够，暂不需要双板。
BRAM9K和PLL比LUT更紧；未使用BRAM32K能否承接某个IP，要检查该IP原语/端口/时钟限制，
不能直接把它们视为可替代49个BRAM9K。
当前21位×32位接口可寻址8MiB，两页实际像素载荷约3.52MiB；七图全缓存约12.30MiB，
超过当前地址空间。这是接口寻址范围，不是对整块物理SDRAM容量的判断。

恢复完整HDMI-A并独立显示另一画面，需要单独预算第二视频链路的BRAM、时钟及存储读流，
再验证两路静态/转场/WAV/刷新共存和时序，当前占用率不能保证该扩展。
第二板适合明确拆分两路独立显示职责；它还会引入通信、同步、供电及素材一致性问题，
不能自动消除当前单卡加载延迟。先完成单板预取版本实物复核，再决定是否拆分。
