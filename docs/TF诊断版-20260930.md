## TF-D1 实现

- 新增只读旁路 `tf_diag_capture`，对现有请求、数据和完成事件计数；不发出 SD 读写请求，不改变扫描地址或目标数量。
- 192 位诊断状态使用请求/应答 toggle 邮箱跨 SD→video 时钟域；发送到应答前保持总线稳定，接收时钟停顿时不覆盖待收快照。
- 原控制器软复位不清零诊断计数，保留复位和超时历史；整板复位才清零。
- 草莓首扇区探针固定在本轮 H: 实测 LBA32784，仅记录既有事务的前 4 个字节。换卡或重新分配文件后，需要重新核对这个探针位置。
- TF-D1 监视台标题明确区分新旧固件；数码管仍显示 BMP 原有 state_code。

## 监视台字段（全部为十六进制）

| 字段 | 含义 | 关键正常值 / 判断 |
|---|---|---|
| TF F/SNE | F 是 16 位标志，SNE 依次为 BMP 状态、已发现数、错误码 | 扫描完成应 N=3、E=0；S=1 只是空闲 |
| TF LBA | 最近一次发给真实 SD 控制器的读地址 | 用来判断扫描是否推进 |
| RD/RESET | 扇区读取完成次数 / 物理控制器软复位次数 | 读取次数应递增；RESET 非零说明曾超时复位 |
| BMP HEAD | 草莓首扇区前 4 字节，按收到次序拼接 | 本卡应为 424D3610，即 BM 和文件长的低两字节 |
| PIXELS | 当前/最后一次装载输出的 BMP 像素数 | 完整 640×480 = 0004B000（307200） |
| WR/SCALE | SRC_BUF 写完次数 / 缩放提交次数（8 位循环计数） | 01/00 且持续不变表示写完但缩放未完成 |

标志 F 位定义：bit0=init_done，bit1=scan_done，bit2=load_busy，bit3=source_done_seen，bit4=display_valid，bit5=load_fault，bit6=retry_used，bit7=存在可用图片，bit8=曾软复位，bit9=曾 BMP 仲裁超时，bit10=曾 WAV 仲裁超时，bit11=至少读完一扇区，bit12=草莓探针四字节齐。

错误 E：0 无错误，1 BMP 头不合法，2 读取超时，3 像素数量不足。

## 板上测试

工程入口仍是 `D:/FPGA/code/example/td_prj/av_media.al`；本轮已编译，可直接使用最终 bit 下载。SRAM 临时下载仍会在断电后失效，断电插卡后需要重新下载 bit。打开工程时若 TD 提示更新，关闭后重新打开工程以刷新文件列表；下载前确认最终时间，不使用 19:17:55 的旧版本。

1. 先在 Windows 安全弹出 H: 再取卡，开发板断电插卡，再上电下载本轮最终 bit；保持供电。
2. 下载完成保持供电，HDMI_A 应出现 `SYS MONITOR TF-D1` 标题；主图依旧在 HDMI_B。
3. 从下载完成起约 30 秒拍摄一次完整 HDMI_A 画面与数码管，约 90 秒再拍一次；保留 TF F/SNE、TF LBA、RD/RESET、BMP HEAD、PIXELS、WR/SCALE。两次快照用于判断读取进度和超时，不是承诺 90 秒内扫完。若只有一块屏，先拍 HDMI_A 再切 HDMI_B，保持板子供电。
4. 无需重新复制、删除或格式化图片。

## 结果判断示例

| 板上字段 | 可定位的阶段 | 下一步依据 |
|---|---|---|
| F bit0=0，RD 一直为 0 | 初始化未完成 | 检查 CMD 响应与 SPI 信号；不能认定图片格式问题 |
| RD 增加，LBA 前进，N 始终 0 | 能读扇区但未识别到图片 | 到达 0x00008010 后观察 HEAD 是否 424D3610 |
| RESET 增加或 F bit9=1 | 读取过程中曾超时 | 结合最后 LBA、读完成次数检查 SPI/控制器恢复 |
| N=3、E=0，PIXELS 少于 0004B000 | 识别完成但图片数据未全输出 | 检查数据有效、BMP EOF、超时及 SRC 写入 |
| PIXELS=0004B000，WR/SCALE=01/00 后一直不动 | BMP 像素输出/写完成，但缩放未提交 | 检查 SRC_BUF、SDRAM、缩放读写和提交握手 |
| SCALE 非零且 F bit4=1，HDMI_B 仍无图 | 已走到显示提交阶段 | 再检查显示页、混合层、输出读帧路径 |

上表是定位方法，不代表这些现象已经在板上发生。计数为 hex 且可能循环；WR/SCALE 后续可大于 01/01。
