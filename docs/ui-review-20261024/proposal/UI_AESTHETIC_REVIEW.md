## 1. 真实结论（≤200字）

**成品度约 76/100：已经是一台"设计过的设备"，不再是工程原型；但顶栏字比内容还重，卡的构图把标签和数值拽到对角。**

三个最突出的问题：

1. **页眉是全局最重的字**：`PROGRAM CONTROL` 用 32×64 物理粗体全大写、15 格铺满 480px，与 64×64 的卡名同高却更粗，在 800×450 预览里成了画面标题，抢走了六张卡的主权。
2. **卡内是"左上标题—右下数值"的对角构图**：数值离标签 34 逻辑像素，单字符值（亮度 `0`、`ON`、`2S`）孤零零挂在 368px 宽的卡角，读作残留标记。
3. **音频页颜色自相矛盾**：`静音 ON` 是薄荷绿（看着像"声音开着"），编辑音量时百分比变琥珀、音量条却仍是绿色（看着像"已生效"）。

主推荐方向：**把页眉降为眉标（1× 32px、无粗重感），把数值改为与标题同列左对齐**；其余保留。HDMI-B 本轮基本无需改动。

## 6. 推荐设计与精确规格

一个首选方向：**"低调页眉 + 同列读数"**——把页眉降为眉标（1×、32px 物理），把每张卡变成"标签在上、读数在其下、同一左列"的数据块。理由：三分钟视频里，观众先看功能再看数值；页眉压下去、读数靠近标签，页面主次立刻成立，且全部靠常量与既有字库完成。

备选方向（仅记录，不推荐本轮做）：保留现有"左上—右下"对角构图，只做 M3/M4 两处颜色与图示修正。差别在于对角构图对单字符值始终偏弱。

提案效果图（HTML 近似，SimHei/Consolas 抗锯齿，**不是 RTL、不是板拍**）：`images/proposal_menu_header_eyebrow_720.png`。它只演示 M1＋M2 后的页眉与卡内关系，颜色、字重以 RTL 现有图为准。

保留项（不改，且应写进后续文档）：

1. **640×360 整数 2× 全幅**：无黑边、笔画严格 2×2、没有 1.5× 的列重复——这是本轮最大的正确决定。
2. **六卡/四卡的网格与 16/20 逻辑间距**：页边与行距成体系，比中央 4:3 时代干净得多。
3. **四色状态语义**：青=焦点、琥珀=未生效、薄荷=开、珊瑚=关/错；除 M3 两处外自洽，且跨两屏复用。
4. **HDMI-B 的四块板 + 16px 内框 + 2px 顶线**：已具备"广播下三分之一"的克制，不再需要加装饰。
5. **64 格单次穿窗**：`scroll/` 抽样帧证明两端不再分段，末段 64px 留白成立。
