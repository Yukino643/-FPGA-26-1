# TF-D2：首图缩放启动与显示页修复

## 板级证据

Julian 的 TF-D1 两次拍照，监视台 UPTIME 为十六进制 2B/5D，即 43/93 秒。

| 字段 | 43 秒 | 93 秒 | 判断 |
|---|---|---|---|
| TF F/SNE | 1881/230 | 188F/130 | 已找到 3 图，错误码 0 |
| BMP HEAD | 424D3610 | 424D3610 | 正确读出 BMP 头 |
| PIXELS | 0 | 0004B000 | 首图 307200 像素已输出 |
| WR/SCALE | 00/00 | 01/00 | 源缓存完成一次，缩放未完成 |
| RESET | 0000 | 0000 | 未发生软控制器复位 |

TF 卡的格式和图片无需修改。照片只能确认截至源缓存完成的链路，不能单凭此认为显示缓存已经写好。

## 根因与修改

| 问题 | 修复 | 失败反例 |
|---|---|---|
| 缩放配置使用只在提交后更新的 cur_img_w/h | 使用本次 bmp_load_img_w/h | 首图启动时旧宽高为 0，缩放无法完成，因而永远无法更新宽高 |
| 顶层将持久 toggle 变成脉冲，模块内部再次边沿检测 | 直接传持久 toggle，由 scaler 唯一同步检测 | 单拍请求被检测成两个边沿 |
| 根据当前显示页反推目标，首图实际待提交页是 0 | 根据 write_buf_idx 选择目标页 | 首图写页 1，却提交页 0 |
| wr_cnt 仅在复位时清零 | 每次任务接受时清零 | 第二张图片从目标页偏移 307200 处开始写 |
| BRAM 读地址丢失 x[9] | 保留完整 x[9:1]，同步读口使用组合地址 | 640 宽图在第 512 列读回第 0 列 |

装载控制器在缩放完成前维持 load_busy，不启动下一图。宽高在 BMP 头解析后锁存，目标页在装载启动时锁存；源写完成后才翻转请求，因此配置在跨域事件同步期间保持稳定。scaler 接受事件后锁存配置。

## 图片已出但颜色错位/花屏：像素字节布局跟进

Julian 后续板照确认 HDMI_B 已经显示 TF 图片，但画面颜色异常、模糊并伴随花屏。对当前源码与学长的 HX4S20 TF→SDRAM→HDMI 例程对照后，发现显示读端的像素位段与当前 scaler 写端不一致：

| 阶段 | 当前工程的数据布局 | 约定 |
|---|---|---|
| BMP 解码 | `bmp_read_g` 输出 `{R,G,B}` RGB888 | 一个像素 24 bit |
| SRC_BUF | `src_packer` 每两个像素打包为 `{odd RGB565, even RGB565}` | 每个 32-bit SDRAM 字含两个 RGB565 像素 |
| scaler 输出 / DISP_BUF | `scaler` 写入 `{out_r,out_g,out_b,8'h00}` | RGB 在 `[31:8]`，低字节保留为 0 |
| HDMI 预取 FIFO | `disp_read_engine` 原样搬运 32-bit SDRAM 字 | FIFO 不改变像素位段 |
| HDMI 混合器 | 应从 `[31:8]` 取 RGB888 | 已修正 `disp_mixer` 的 A/B 两路切片 |

学长工程 `D:/FPGA/25年国奖代码/fpgaa/Main/q3q4/lab_ex_6_tf_sdram_hdmi/src/top.v` 将 `video_read_data[31:8]` 接入 `video_delay.read_data`，与此布局吻合。相应回归夹具也改为在 SDRAM 模型中放置 `32'hRRGGBB00`，并新增 `tb_disp_pixel_format` 用非灰度样本检查实际输出通道。

用户给出的《全国大学生嵌入式芯片与系统设计竞赛 2025 安路赛道选题指南》截图显示题目是“基于安路 FPGA 的以太网数据传输系统”，图片显示/收发是基础要求之一；该竞赛链路是以太网与 PC，TF 卡不是题目规定的数据来源。学长的 TF 例程可作为同一 HX4S20C/EG4S20BG256 板卡的 SDRAM 和 HDMI 接口参考，不能据此推断整套 TF 逻辑就是竞赛必需实现。

| 源码写端布局与显示读端切片不一致 | 已确认的 RTL 根因，足以造成颜色通道错位与异常暗色 |

## D3 板照 `01/4C` 后续诊断

照片中的 `4C` 解码为 scaler S_FDA、busy=1、C-valid=1、C-ready=0、done=0。这证明缩放器已发起读请求但未被仲裁器接受，不能据此单独区分控制器未初始化、上一笔事务未收完或高优先级请求占用。官方 `frame_fifo_read` 会等 `Sdr_init_done`；当前 mem_mpu 原先没有 init/busy 接受门控，且只在命令结束后的 drain 状态计数响应，因此已增加接受门控及命令期间响应路由，并以固定短延迟模型覆盖命令/返回重叠。

同时将 scaler 的整字 DQM 从 `4'hF` 改为 `4'h0`。官方 SD 写路径给出的 `App_wr_dm=0`，标准 SDRAM DQM 高电平用于屏蔽字节；此前的 `4'hF` 会屏蔽缩放像素整字写入。行为模型现按每字节 DQM 屏蔽语义写入，联调检查 scaler 输出未屏蔽写。
