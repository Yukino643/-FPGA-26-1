# TF-D2：首图缩放启动与显示页修复

## 板级证据

Julian 的 TF-D1 两次拍照，监视台 UPTIME 为十六进制 2B/5D，即 43/93 秒。

| 字段 | 43 秒 | 93 秒 | 判断 |
|---|---|---|---|
| TF F/SNE | 1881/230 | 188F/130 | 已找到 3 图，错误码 0 |
| BMP HEAD | 424D3610 | 424D3610 | 正确读出 BMP 头 |
| PIXELS | 0 | 0004B000 | 首图 307200 像素已输出 |
| WR/SCALE | 00/00 | 01/00 | 源缓存完成一次，缩放未完成 |
| RESET | 0000 | 0000 | 未发生软控制器复位 |

TF 卡的格式和图片无需修改。照片只能确认截至源缓存完成的链路，不能单凭此认为显示缓存已经写好。

## 根因与修改

| 问题 | 修复 | 失败反例 |
|---|---|---|
| 缩放配置使用只在提交后更新的 cur_img_w/h | 使用本次 bmp_load_img_w/h | 首图启动时旧宽高为 0，缩放无法完成，因而永远无法更新宽高 |
| 顶层将持久 toggle 变成脉冲，模块内部再次边沿检测 | 直接传持久 toggle，由 scaler 唯一同步检测 | 单拍请求被检测成两个边沿 |
| 根据当前显示页反推目标，首图实际待提交页是 0 | 根据 write_buf_idx 选择目标页 | 首图写页 1，却提交页 0 |
| wr_cnt 仅在复位时清零 | 每次任务接受时清零 | 第二张图片从目标页偏移 307200 处开始写 |
| BRAM 读地址丢失 x[9] | 保留完整 x[9:1]，同步读口使用组合地址 | 640 宽图在第 512 列读回第 0 列 |

装载控制器在缩放完成前维持 load_busy，不启动下一图。宽高在 BMP 头解析后锁存，目标页在装载启动时锁存；源写完成后才翻转请求，因此配置在跨域事件同步期间保持稳定。scaler 接受事件后锁存配置。

## D3 诊断字段

标题改为 `SYS MONITOR TF-D3`。`WR/SCALE` 右侧字节改为 scaler 状态快照：高四位是状态机（0空闲、1除法、2行处理、3/4读源、5输出、6完成），低位依次为 busy、C口 valid、C口 ready、done toggle。D3 仍保持 TF 卡只读，不额外发起 SD 访问。

新增行为级联调 `sim/tb_scaler_mpu.v`，覆盖 scaler、mem_mpu 和 SDRAM 返回延迟；完整回归为 basic27/27、full28/28、独立 check_reports fails=0。
