## 4. 前轮已实施修复（保留实现依据）

| 原问题 | 修复与时序保证 |
|---|---|
| 黄色条纹倾斜 | 不再用每行DE上升沿推进；只在有效帧首坐标(0,0)推进一次，整帧同相位。32像素周期低位加法替代 `%40`，避免10bit横坐标截断，不增加视频级数 |
| 不能返回图片按键 | KEY2长按松开退出菜单且丢弃未确认预览；播放模式KEY2短按下一张、KEY3短按自动，KEY3长按松开重进菜单；菜单内KEY3长按翻页 |
| 待提交正文被预览覆盖 | 控制器单独输出已提交`cfg_payload`并保持至ACK；视频域只在VS应用该正文，预览另行同步，已发出的提交不因退出而撤销 |
| 退出后退回旧参数页 | HDMI-A始终显示同一四卡控制台；播放模式隐藏黄色光标并显示PLAYBACK KEYS及两行提示；移除旧参数页实例，不新增帧缓存/PLL |
| 底部按键提示破碎 | 修复ASCII字库列地址，并检查固定字符串长度，避免字形被压坏和首字符截断 |
| 菜单组合计算直通TMDS导致负余量 | HDMI-A坐标、字库与RGB共三拍，HS/VS/DE同步对齐；TMDS前缀变换和偏差输出再分两级。真实顶层提取仿真核对完整720p有效区、黑边和卡片边界，独立逆解码检查TMDS像素/控制符/线路偏差。最终余量以本轮物理报告为准 |

## 6. 底层审查与限制

| 维度 | 结论 |
|---|---|
| 寄存器/副作用 | 本轮是RTL控制寄存器，不涉及CPU外设读改写；commit toggle一次确认只翻转一次 |
| 内存模型/CDC | 多位正文用独立保持邮箱并等待ACK，预览只供监视；异步按键有同步与消抖。状态显示的多位统计仍是逐位同步，不适合当原子故障快照使用 |
| 中断 | 本工程按键是硬件状态机事件，没有CPU中断优先级；冷图等待来自存储/缓存/转场流程 |
| 时序 | 应急动画每帧更新；HDMI-B RGB/DE级数未增加，HDMI-A输出增加同相寄存；真实setup/hold必须看本轮布局报告，仿真不能代替时序闭合 |
| 启动 | 菜单复位直接开启；图片正文默认0111；Flash断电启动仍需板验 |
| RTOS | 无RTOS，不适用任务调度/优先级反转审查 |
| 边界/安全 | 720p横坐标高位不再被错误截断后做40取模；提交忙时不能发第二笔提交；长按不会再产生播放器短按事件 |
| 可移植性 | 使用Verilog-2005及现有安路工具链；应急相位寄存器沿用可综合初值启动，移植不支持初始化的器件时应增加显式复位 |

失败反例：把`cfg_shadow`直接作为待提交正文，会让“确认关闭图片后，在下个VS前预览重新打开”错误地提交打开；因此预览与正文必须分离。把DE的每次上升沿当成帧首，会让每行横向相位不同；必须用VS或对齐后的帧首坐标。

当前单板没有功能上必须引入第二块板子的证据。优先减少无用显示链路、限定像素算术宽度、保持BRAM字库与低成本动画；是否需要第二块板应由完整资源/时序/带宽报告与新增功能预算决定，不能仅因达到720p便推导必须双板。
