# RV16无声视频实验契约

适用分支feat/raw-video-320x180；设计与限制见docs/raw-video-20261025/。

- 实验RAW_VIDEO_MODE=1替换图片加载/转场，HDMI-A控制台保留；0保留图片系统。不得把实验模式资源减少量当作完整图片功能下的优化结果。
- PC先把MP4转换为RV16；FPGA只处理320×180/10fps/RGB565小端bottom-up帧流，不得宣传MP4/HEVC硬解码。512字节头严格校验，帧长115200B/225扇区；文件总长使用33位检查。
- FAT索引扩展名参数默认BMP，视频实例R16。必须跟随真实碎片簇链，循环从文件起点重定位；不逐帧扫描根目录或解析BMP。
- source_restart之后必须先保持write_req低并等旧ACK回低，给source_scaler_gate重新武装；禁止同拍restart和新请求。新源解析和源writer均完成后启动scaler。
- 复用紧凑源暂存与两个720p目标页/行缓存。整页写完才发布，SD pending同拍锁定；视频6VS边界采纳后通过返回toggle释放，直到释放前稳定页号且不复用旧页。迟到保持旧页，不补播积压帧。
- 故障不load_done/commit，不显示半帧；错误后需复位。普通WAV在首阶段关闭，不等于已实现视频音轨同步。
- 有效带宽预算：源1.152MB/s，目标720p写18.432MB/s，60Hz显示读110.592MB/s；这些不是实卡测试结论。
- 必测真实SPI字节周期、碎片读取/循环、RGB565、坏头/短读/超时/中止/无文件/总长、6VS早到迟到、真实writer/scaler/arbiter完整720p像素与刷新阻塞；上电预取前欠载与播放后新增欠载分列。
- Icarus墙钟超时不算PASS；可用同一测试台编译仿真，不得删减断言冒充通过。PyPI包装版本与运行器版本分别记录。
- 发布须原回归88/88、视频仿真输入SHA匹配、完整P&R/bitgen、video setup≥0.15ns、其他域内setup/hold非负、BRAM9K≤57、BRAM32K≤4、DSP≤15、PLL≤3；旧SDRAM跨域−6.565ns单列。

## 运行时融合契约

- `RAW_VIDEO_MODE`仅作为默认模式兼容参数；融合版上电图片，HDMI-A可切换视频/暂停/返回，不得沿用“仅替换图片”的实验版功能说明。
- 切换必须按阻止新源、当前源/缩放/转场收尾、VS持页确认、真实存储突发排空、各域媒体复位握手、ACK回低重新武装的顺序执行。不能用固定等待周期冒充事务完成；PLL、HDMI时序、SDRAM硬核、显示读链、菜单及应急不参与媒体复位。旧版融合bit主动黑场仅为历史实现，不能继续作为当前契约。
- SD域首帧必须写锁存完整front的反页，视频域retain_display保持旧front；新图片完整后才进入淡化。开机首图及普通切图仍32VS，视频返回首图可用参数门控8VS；首笔提交时锁存属性，不得跟随之后撤销的持页信号改变在途步长。显示FIFO不随媒体复位清空，不得把保持时序等同于保持完整图像。
- 暂停时完整待提交页可能占住邮箱；切模式时允许待提交页释放。视频域仅在两级同步switching_video后绕过4800样本预算，仍要求完整页和VS；正常播放不允许绕过。必测“暂停且有pending帧、预算不足4800样本时返回图片”，避免停止音频生产后永久等预算。
- RV16 v2在视频帧区后追加48kHz/signed16LE/双声道PCM，v1仍无声兼容。独立FAT游标读取音轨，复用原wav_read扇区BRAM与audio_player FIFO，不新增音轨大缓存；严格校验头字段、位置、数量和总长溢出。
- 首页要求至少256样本预取，每视频帧消费4800样本，正常6VS提交；慢帧时预算末静音等待，暂停保留FIFO和音轨位置，循环尾首连续。音轨读错静音并报告，不发布半视频页。
- 视频模式停止普通WAV并复用PCM路径，切换收尾等待音频真实idle，媒体复位清音频FIFO；全局48kHz节拍不复位。返回图片从头重启WAV，不再恢复旧WAV位置。应急警笛与原音量控制优先级保留。旧无声融合发布的WAV后台继续策略仅为历史行为。
- FAT超时仅作用于WAIT态；不得让WAIT专用超时控制扇出门控全部MBR/BPB字节解析寄存器。将异常覆盖收敛到状态/错误/完成寄存器时，须证明与sector_done互斥并验证精确到期拍与done优先级。
- 同一bit发布须绑定全部仿真输入SHA、当前源码清单、物理数据库及定向时序摘要SHA。实验版已板验不代表融合版已板验。
- 32位文件大小下，文件扇区数量保留24位，有效下标可用23位；高位请求必须显式拒绝，不得截断成合法低地址。簇号/LBA保留32位，链长/超时按参数取clog2并至少1位。边界测试须覆盖最大文件末扇区、65535链接、非法高位不发IO、恰好链长上限、精确超时与done同拍优先。
- 头长度计算必须在已验证帧数之后分拍完成，禁止把帧长/音轨长/文件总长宽算术串到client_req/file_start控制路径。文件总字节比对保留溢出位，v1/v2所有1..65535帧以独立64位参考覆盖。
- 有声融合资源版删除整个外设检测页及菜单蜂鸣测试，KEY3长按直接节目↔媒体；保留真实LED与应急蜂鸣器。中文回收外设专用槽位，36字BRAM+1字逻辑，不增加字库银行。
- 流式BMP时序优化不得改变有效字节/像素相位。将范围比较改为边界标志时，必须覆盖offset=0、非标准offset、文件末字节、valid连续/间歇、32位计数回绕语义，并以固定旧源逐拍验证，不能用新实现生成参考。
- 返回首图提速仍保留完整页、VS启动、255饱和及SETTLE后释放；默认参数必须与固定旧源码逐拍等价，普通/返回/后续分别验证32/8/32VS，四组媒体流水与原功能完整回归不得删减。24VS约0.4秒只代表动画节省，不代表真实卡总返回时间；禁止为此新增页缓存或跳过事务排空。
- FAT游标比较若分拍，目标/当前游标每次修改后必须重新比较，禁止消费旧关系；原事务超时和done优先规则不变。缩放阈值预减依赖fit_h>=height，只限当前等大/放大契约，多尺寸测试用独立坐标公式逐像素核对。

## 返回首图提速参数契约

1. 范围：仅视频返回的首张完整图片；图片读取、缩放、音频和应急路径不变。
2. 签名：`transition_ctrl.RETURN_SPEEDUP=0`、`RETURN_ALPHA_STEP=32`；输入 `return_from_video` 为 clk 域单比特。顶层启用并连接已有 `retain_display_v`。
3. 正文：复位重置 first_commit；首笔有效 commit 在 IDLE 且无 pending 时锁存 `RETURN_SPEEDUP && first_commit && return_from_video`；事务中外部输入变化无效。
4. 错误：开启功能但步长为0须仿真 fatal；alpha 用9位求和并饱和255；不允许绕过完整页、VS或SETTLE。
5. 用例：基础上电32VS、正确返回8VS、紧接普通切图32VS；反例是首笔提交后撤销 return 信号导致动画中途变速。
6. 验证：`python -X utf8 scripts/verify_media_return.py` 固定旧参考逐拍等价及1462拍输出检查；原完整回归和pipeline0/1/2/7全部保留；新转场寄存器双向定向时序须单列。
7. 错误/正确：全局修改 ALPHA_STEP 会改变普通切图；正确做法是可选门控并在提交时锁存首张属性。24VS约0.4秒只记录动画收益，真实卡总耗时需板测。
