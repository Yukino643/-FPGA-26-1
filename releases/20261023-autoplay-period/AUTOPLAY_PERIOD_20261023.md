# 自动轮播实际周期修复（2026-10-23）

## 1. 修改范围与结论

当前预取模式档位改为 **2、3、5、10秒**，按用户要求去掉1秒档。周期含读卡、缩放和转场，按一次显示发布到下一次显示发布之间的时间计算；不再等缩放/转场结束后才重新数完整周期。

本轮软件验证、构建和发布不代表用户已上板确认新周期。旧版音量/多尺寸已板验版本保留在 `releases/20261023-audio-volume/`，SHA256为 `8e3930111f9329802128d4e9b56c3eec628c9ef264899636245f87d1db93ad68`。本轮不修改TF卡，不下载、不固化Flash，不自动提交或推送Git。

## 2. 根因与复现证据

| 取证 | 结果 |
|---|---|
| 本机原RTL | `sd_card_bmp_g` 在 `hold_load` 为1时清零 `auto_cnt` |
| 真实顶层 | `hold_load`包含显示提交等待、转场和缩放busy，耗时被反复从周期中排除 |
| 时钟核查 | SD域100MHz，`CLK_FREQ_HZ`也是100MHz，未发现“秒”分频设置错误 |
| 原RTL负向测试 | 缩比模型设5秒，读卡0.2秒、缩放2.2秒、转场0.55秒，三次提交间隔均7.953秒，测试按预期失败 |
| 修复后同一场景 | 三次均5001个缩比SD拍（目标5000），消除额外2.953秒等待 |

7.953秒是仿真模型复现，不是对用户板子重新测得的精确时间。旧RTL来自修改前Git提交 `a9487636be0adf032883c2c0c0877bd9a756bb2c`，日志为发布目录 `validation/before-negative-control.log`。

## 3. 实现规则

| 位置 | 修改及边界 |
|---|---|
| `rtl/sd/sd_card_bmp_g.v` | 预取模式2/3/5/10秒；忙时继续计时；到期挂单次自动请求并冻结，不累计欠下的周期 |
| 相同模块 | 实际显示发布、修改周期或自动开关时清计数/旧自动请求；到期比较使用大于等于；关闭自动与到期同拍时关闭优先 |
| 相同模块 | `prefetch_ready && !hold_load`继续保护发布，不能为了准点发布未完整写好的图；手动队列保留，手动切图重新计自动周期 |
| 兼容模式 | `PREFETCH_NEXT=0`保留历史1/2/5/10秒装载调度，不改变旧夹具的行为；当前720p顶层使用预取模式 |
| `rtl/video/monitor_menu_renderer.v` | 周期卡对应显示2S/3S/5S/10S，不增加字体、画面缓存或像素路径算术 |
| `rtl/sd/fat32_file_sector_mapper.v` | 首次P&R发现既有LBA长算术路径，复用地址寄存器拆开减法、移位、两次加法；仅最终LBA稳定后发请求，增加30ns/数据扇区 |
| `td_prj/flow_fixhold.tcl` | 拆拍后seed17遇局部增量布线冲突，seed13的SD/视频通过但内存域连线过长；小范围调整官方布局seed，最终值见构建结果。保留LogicLevelOptimize、高扇出优化、routability及hold修复，不改SDC/频率/验收门限 |

周期选择已经在SD域，未增加多位总线裸跨域。真实视频提交沿用原toggle/ACK与页释放保护，未改变图片几何、声音音量、字幕或应急逻辑。32位最大计时10×100MHz=10亿拍，小于32位范围；到期冻结，避免长期等待回绕。

| 底层审查维度 | 结论 |
|---|---|
| 寄存器访问 | FPGA时序寄存器，没有CPU MMIO读改写；多分支赋值核对关闭/确认优先级 |
| 内存模型 | 不引入DMA或CPU缓存；原帧页完整写入与释放保护保留 |
| 中断系统 | 无CPU中断；按键沿用已分类事件，不增加短长按冲突 |
| 时序 | SD计时、帧边界等待和素材吞吐分开；域内setup/hold由最终P&R验证 |
| 启动流程 | 计数/档位历史/待请求复位明确，默认最短2秒，自动仍默认关闭 |
| RTOS | 不适用，无新增任务/锁；请求仅单项饱和等待 |
| 安全性 | 计数不回绕，不把未完成页发布；LBA拆拍中间值不发扇区请求 |
| 可移植性 | 显式32位计数和2位档位；TD综合、Icarus仿真分别验证 |

## 4. 四档测时（仿真，不是实机）

测试以1000个SD拍代表模型1秒缩短仿真时间，真实SD/video异步时钟及当前顶层提取的整页完成门、CDC和 `transition_ctrl(ALPHA_STEP=8)`均参与。SD卡/缩放完成耗时由环境产生，没有模拟整张物理TF卡或全部SDRAM像素。

| 设置 | 提交间隔：三次缩比SD拍 | 转场开始到下次转场开始：三次模型秒 |
|---|---|---|
| 2秒 | 2001 / 2001 / 2001 | 2.000 / 2.000 / 2.000 |
| 3秒 | 3001 / 3001 / 3001 | 3.000 / 3.000 / 3.000 |
| 5秒 | 5001 / 5001 / 5001 | 5.001 / 4.999 / 5.001 |
| 10秒 | 10001 / 10001 / 10001 | 10.000 / 10.000 / 10.000 |

管理器固定多1拍是先锁存到期请求再发布，真实100MHz下为10ns，不是增加1ms。表中模型秒的±0.001来自缩比和异步帧边界采样，不能把这个数字作为实机误差保证。真实屏幕提交须等60Hz帧边界，正常就绪条件下容差按约一帧16.7ms评估，另有很小的CDC延迟。

| 额外场景 | 验收结果/规则 |
|---|---|
| 长缩放5秒档 | 目标5000拍，三次5001拍，无叠加等待 |
| 自动保持开启，分别改2/3/5/10秒 | 改档后首个转场为2013/3012/5013/10012拍，均在新周期加一帧等待以内 |
| 10秒已运行3.5秒改2秒 | 新周期重新计时，无错过相等比较后等待32位回绕 |
| 读卡5.2秒超过最短两周期 | 只保留一个待请求，未就绪安全延后；不会恢复后连续补切 |
| 到期后关闭、关闭与就绪同拍 | 撤销自动请求，不泄漏一次切图 |
| 手动切图 | 自动周期重启，不紧跟遗留自动请求连跳 |
| 菜单四档 | 独立ASCII字模参考逐档核对5120个状态文字像素 |
| FAT32拆拍 | 独立乘法参考覆盖全部1/2/4/8/16/32/64/128扇区每簇、簇内首尾、大数进位；原碎片链、回退、边界、自环、超时测试保留 |

## 5. 操作与板级验收

1. 下载本次独立发布的bit。开机仍在HDMI-A主控制页，下排中间是“周期”。
2. KEY2/KEY3短按选择“周期”。第一次KEY4把周期向前切一档并显示预览，第二次KEY4确认；每两次KEY4前进一档，循环为2→3→5→10→2秒。未确认时短按KEY2/KEY3只移动光标，不改变HDMI-B。注意不要留有其他卡未确认的预览再操作周期卡；可先长按KEY2取消预览，再重新进入菜单。
3. 确认后从新档位重新计时。按约1秒KEY2并松开，逐级取消/返回到播放按键模式；若已无未确认预览，主页面长按KEY2直接退出菜单。
4. 播放按键模式中，KEY3短按开启/关闭自动轮播，KEY2短按下一张。KEY3长按重新进入菜单。长按KEY4仍保留应急。
5. 每个周期档连续测5次，取相同画面标志：“新图片开始淡入”到“下一张开始淡入”。不要一端用开始淡入、另一端用完全显示，这会混入约0.55秒转场差异。
6. 各档重复测试当前TF卡的720p及640/960混排，音频保持开启；播放中由10秒改2秒和由2秒改10秒也各测一次，确认以改档确认重新起算。
7. 注意：不承诺任何卡/任意素材都能2秒准备完成。卡慢、重试或缩放超时会安全延后；如果2秒档仍超出，记录具体图片编号及原图分辨率，再实测准备耗时决定是否提高最低档。不能为了秒表准点显示未完成页面。
