# TF 音频启动优化（2026-10-22）

## 诊断与方案

| 环节 | 原行为 | 本轮行为 |
|---|---|---|
| 启动条件 | 等第一张图片提交 | FAT32目录定位后即可启动 |
| 找WAV | 从LBA0逐扇区比对RIFF/WAVE，最多65536扇区 | 复用同一次根目录扫描，读取首个WAV短文件项的首簇 |
| 地址 | 每检查一扇区加1 | data_start_lba + ((first_cluster−2) << spc_shift)，分拍计算 |
| 文件头 | 扫描命中后重新读首扇区 | 候选首扇区验证后流式读取，坏头只检查该扇区 |
| 图片加载 | 先首图，再扫描WAV | 图片/音频按现有不可打断的扇区轮转 |
| 无WAV | 最坏扫描65536扇区 | 正常目录结束后静音 |

瓶颈在文件定位，并非软件中断优先级。当前系统没有用于文件切换的CPU中断。SD SPI高档为25MHz，单纯读取32752个512字节扇区的载荷就至少需要约5.37秒；命令、token和BMP竞争还会增加时间。这是计算例，不能视为用户当前TF布局或实测时间。

## 已完成实现

1. BMP索引可选开启WAV发现，默认关闭以兼容旧实例；当前顶层开启。
2. 达到8张图片后，若尚未找到WAV，仍检查后续根目录扇区/簇；正常结束、链上限、错误和超时保持有界。
3. 忽略删除/LFN/目录/卷标、簇越界、短文件和00结束后的残留目录项，只记录首个合法WAV候选。
4. 首簇换算分三拍，扫描无错误后才发布；SD重新初始化清除有效标志，不沿用旧卡地址。
5. 取消首图等待，候选只验证一个扇区；没有候选或头不匹配保持静音。
6. 不增加帧缓存、PLL或整段音频缓存，不改TF文件、UI或SDRAM逻辑。

## 仿真结果（并非上板出声时间）

固定模型：100MHz、每拍返回一个SD字节、音频位于物理LBA2057，首图负载为100个扇区；小FIFO饱和后模拟48kHz取样资格。实际SD卡SPI字节返回更慢，真实BMP装载和缩放也不等于该100扇区模型。

| 测量 | 旧基线控制 | 新的真实顶层控制 |
|---|---:|---:|
| 首PCM时钟拍数 | 1,122,194 | 3,642 |
| 首PCM前总扇区请求（含目录/图片/音频） | 2,162 | 8 |
| 模拟首图完成拍数 | 53,563 | 56,653 |

模型中首图约增加5.8%，音频定位读取显著减少。这个比例只适用于该模型；不能保证任意卡/音频/图片均为相同比例。`sim/fixtures/wav_startup_legacy.v.txt`取自db94c03原顶层WAV控制，当前方案从真实top提取，避免理想控制模型冒充修改后的实现。

新增5项回归：目录边界、启动与旧方案对比、坏头单扇区退出、无音频零WAV请求；包含重初始化后再次产生PCM。原有WAV PCM序列/跨扇区/背压及音频节拍测试继续保留。

## 兼容边界

- WAV请放在FAT32根目录。选择根目录中第一个合法WAV短文件项对应的文件；带长文件名的正常短目录伴随项也可匹配。
- WAV沿用已验证的标准44字节头、48kHz、16bit、双声道PCM和物理连续扇区存放前提。本轮没有增加碎片簇链音频播放或通用RIFF chunk解析。
- 原始扫描可能误认目录外/已删除文件残留的新旧行为不再保留；正式文件应通过目录访问。
- 不自动重写/整理TF卡，也不执行旧的`scripts/sync_to_sd.py`。

## 上板计时

1. 保持同一张TF卡、同一WAV、同一屏幕和相同接线，先用原版记录从上电到首图、从上电到首声的时间。
2. 下载本轮验收后的独立bit，重复冷上电至少5次，记录范围；避免用下载后热复位冒充冷上电。
3. 确认首图、持续声音、PCM波形正常；播放期间切图20次，检查无音频中断和图片颗粒。
4. 若首PCM已经明显提前但屏幕仍延后出声，需要单独测量HDMI接收器的解码/静音释放时间，不能继续盲改SD等待。
